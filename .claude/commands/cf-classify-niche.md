Следуй промпту prompts/agents/niche-classifier.md. Аргументы: $ARGUMENTS
(первым позиционным аргументом — вкладка, напр. `/cf-classify-niche raw_instagram`;
без аргумента по умолчанию tab=raw_tiktok). Конвейер фан-аута вызывает команду
по одному разу на каждую raw-вкладку, передавая ключ вкладки явно — так
классифицируются обе (raw_tiktok и raw_instagram), а не только TikTok.

Ключевые точки:
- `--reaudit [ниша]` → режим «Ре-аудит» из промпта агента: перепроверка УЖЕ
  проставленных ниш (всей вкладки или одной ниши), файл исправлений *-reaudit.json.
- `--clusters <tab>` → режим «Режим кластеризации» из промпта агента: `.venv/bin/python -m cf cluster-other`
  уже посчитал кластеры → сформируй предложения новых ниш
  (`agent-runtime/niche-proposals/*.json`) → покажи оператору сводку по кластерам
  (взято/пропущено, размеры). Ниши сам не добавляешь — решение за оператором.
  Принятая оператором ниша начнёт давать брифы только после авторинга
  `prompts/briefs/{niche}/reel.md` (по образцу `prompts/briefs/мужские-образы/reel.md`
  и `_shared/schema.md`) и активации `.venv/bin/python -m cf log-prompt-version --prompt-id brief-{niche}-reel …`.
  Напомни об этом оператору в сводке по каждой принятой нише.
- Список ниш — из `prompts/agents/niche-taxonomy.json` (единственный источник
  истины); классификация только по нему.
- Запись в таблицу — только через `.venv/bin/python -m cf apply-niches` (вся колонка одним вызовом API).
- Большой батч (сотни строк) классифицируй частями через субагентов, чтобы не
  переполнить контекст; каждый пишет свой фрагмент mapping-файла.
- После применения предложи оператору `/cf-profile <tab>` — проверить готовность батча.
