# Content Factory — витринная копия

Это витринная копия репозитория Content Factory: контент-завода для бренда мужской одежды
JE LA PECHE. Она собрана из рабочего репозитория одним коммитом, без секретов и данных компании.
Исходный `README.md` рядом — «база знаний для человека» про саму систему (актуален на 26.07.2026);
`AGENTS.md` — действующие правила для агентов. Этот файл объясняет, что перед вами и чего здесь нет.

## Что это за система

Ежедневный конвейер: собрать чужие «залетевшие» короткие ролики в нужных нишах (TikTok, Instagram),
посчитать, какие приёмы реально работают, вывести из них рецепты и написать по рецептам сценарии
для съёмки. Человек принимает одно решение — что снимать. Принцип: **агент оценивает смысл, код
применяет правила, человек принимает бизнес-решение**; агенту не отдаётся то, что проверяется
детерминированно.

Стек: Python 3.12, FastAPI-дашборд, gspread (Google Sheets как операционное хранилище), Apify,
Claude Code как исполнитель агентов (по подписке, не по API-ключу), systemd, Caddy, Telegram Bot API.

## Архитектура (по `docs/FINAL-PROJECT-2026-07.md` и коду)

- **Агенты.** На защите проекта 29.07.2026 их было 12 (`prompts/agents/*.md`): классификатор ниш,
  профайлер батча, аналитик паттернов, автор и судья рецептов, генератор, ревьюер и правщик
  сценариев, eval-агент, оптимизатор промптов, тюнер источников, автор промптов тем. В августе
  добавлен тринадцатый — `vision-cover` (разбор обложек и кадров). Слэш-команд — 14
  (`.claude/commands/cf-*.md`).
- **Цикл из 15 этапов**: сбор → разметка тем → анализ приёмов → черновики рецептов → ворота →
  черновик промпта темы → ворота → сценарии → ревью → доработка → ворота → съёмка и публикация →
  статистика → eval → правка промптов → снова сбор.
- **Трое ворот, human-in-the-loop там, где деньги.** Двое ворот (одобрение рецептов, включение
  промпта темы) закрывает машина — детерминированный чек-лист плюс вердикт агента-судьи; третьи
  (одобрение сценариев) остаются за человеком, потому что дальше съёмка. Политика каждых ворот —
  строка `gates.policy.<ворота>` в конфиге (`auto`/`manual`), возврат в ручной режим стоит одной
  строки. Калибровка на прошлых решениях оператора — `cf gate-calibration`.
- **Трассировка.** Для любого сценария восстанавливается цепочка
  `source_url → pattern_id → formula_id → brief_id → prompt_version → reel_id → performance`
  (`cf trace <brief_id>`).
- **Честное `insufficient_data`.** Если выборка не даёт вывода, агент пишет `insufficient_data` и
  перечисляет, чего не хватает. На 29.07 таких было 69 прогонов из 567 в журнале.
- **Промпты меняются только машинно проверенным путём**: агент не пишет в `prompts/**` напрямую
  (deny-правила Claude Code и PreToolUse-guard Codex), правка действующего промпта идёт кандидатом
  в A/B, а не заменой; снапшоты утверждённых рецептов в `formulas/_approved/` иммутабельны.

## Как устроен harness

- `CLAUDE.md` — симлинк на `AGENTS.md`: один канон правил для Claude Code, Codex и других агентов
  стандарта agents.md, с бюджетом до 32 KiB (Codex обрезает лишнее молча; это держит тест).
- `.claude/settings.json` — allow-список безопасных подкоманд `cf` и deny-правила на прямую правку
  промптов, команд и снапшотов. `.codex/` — то же зеркалом для Codex: `config.toml` (сеть в
  песочнице для Sheets API), `hooks.json` + `hooks/guard_protected_paths.py` (guard защищённых
  путей), `rules/cf.rules` (`git push` только с явным подтверждением).
- Слэш-команды `.claude/commands/cf-*.md` — канон; их Codex-обёртки в `.agents/skills/cf-*/`
  генерирует `cf codex-sync`, дрейф ловит `tests/test_codex_compat.py`.
- Скиллы: скиллпак `mattpocock/skills` (состав — `skills-lock.json`) вендорится в
  `.agents/skills/`, в `.claude/skills/` — симлинки; проектные скиллы `cf-demo-eval-loop`
  и `cf-ui-rethink` лежат там же. Конвейер разработки: `/grill-me` → `/to-spec` → `/to-tickets`
  → `/implement` → `/code-review`; тикеты — `docs/plans/<фича>/issues/`.
- `docs/superpowers/` — архив восьми планов 09–25.07 по методике superpowers, списанной 28.07
  (причина записана в `AGENTS.md`); хранится как evidence.
- Каждый прогон агента — строка в CF Run Log (`cf log-run`); решения по воротам — append-only
  журнал `formulas/_decisions.jsonl`.

## Как запустить локально без Google Sheets

```bash
python -m venv .venv
.venv/bin/pip install -e ".[dev]"                                # Windows: .venv\Scripts\pip
PYTHONUTF8=1 .venv/bin/python -m pytest -q -p no:cacheprovider   # в копии: 2 192 passed, 14 skipped
.venv/bin/python -m cf --help
```

На Windows тесты запускать с `PYTHONUTF8=1` (PowerShell: `$env:PYTHONUTF8=1`), иначе три теста
падают на кодировке консоли cp1251 (`test_dashboard_runner.py` ×2, `test_vision.py` ×1).

Что работает без внешних сервисов: тестовый набор (сеть в тестах запрещена автоматически,
Google Sheets эмулирует `tests/fakes.py`, дашборд гоняется через TestClient), `cf validate`
для артефактов по схемам из `schemas/` (примеры — `tests/fixtures/`), чтение и проверка
конфига. Конфиг берётся из `cf.config.json` или переменной `CF_CONFIG`; за основу — 
`cf.config.example.json`.

Что не запустится без инфраструктуры: всё, что ходит в Google Sheets (`cf read`, `cf status`,
`cf trace`, дашборд `cf dashboard` с живыми данными), сбор через Apify (`cf collect`), звенья,
которые спавнят `claude` подпроцессом (фан-аут ниш, `cf vision`), уведомления в Telegram,
systemd-юниты из `deploy/`.

## Что не включено в витринную копию

- **Данные компании**: реальные реестры источников (`sources/*.json` заменены двумя вымышленными
  записями в `*.example.json`), утверждённые рецепты сверх трёх примеров в `formulas/`,
  source-proposals с реальными хэштегами и запросами. Формулы — результат работы системы на данных
  компании, поэтому в копии их ровно три, чтобы показать формат и цепочку снапшот → черновик.
- **Рабочий конфиг** `cf.config.json` не публикуется; `cf.config.example.json` повторяет его
  структуру с плейсхолдерами вместо идентификаторов таблиц, форм и счётчиков; ставки блока
  `payout` в нём — условные значения-примеры, не пилотные.
- **Исследования, найм, рабочие передачи и память агентов**: исследовательские материалы,
  документы найма (условия отборочных задач и рубрика в `src/cf/hiring/` заменены плейсхолдерами,
  ответы кандидатов в фикстурах `tests/test_hiring_*.py` — синтетические; сам контур синхронизации
  анкеты оставлен), передачи между сессиями, `.claude/memory/`.
- **Списанный слой n8n** (`n8n/`): от него ушли 24.07.2026, причина описана в `README.md`
  и `docs/n8n-integration.md`; тесты паритета с его JS-эталоном в копии пропускаются.
- Отдельный модуль слежки за загрузкой объектов размещения, живший в этом же репозитории,
  оформляется самостоятельным проектом и сюда не входит.
- **Шрифты Aeroport** (коммерческая лицензия) не поставляются: дашборд использует Montserrat (SIL OFL,
  `src/cf/dashboard/static/fonts/THIRD-PARTY.md`) и системные шрифты.
- Адреса, имена пользователей и идентификаторы заменены плейсхолдерами вида `<VPS_IP>`, `<user>`,
  `<SPREADSHEET_ID>`; хосты инфраструктуры — на `cf.example.com` / `n8n.example.com` (публичный сайт
  бренда `jelapeche.com` оставлен); локальные пути рабочей станции — `<local-path>`; имена людей — ролями.
- Ссылки в исторических документах (в том числе в `README.md`) на невключённые файлы —
  `docs/BUSINESS-CONTEXT.md`, `n8n/`, `docs/HANDOFF-*.md`, `docs/research/` — намеренно не переписаны.

## Статус проекта

Цифры на 29.07.2026 (`docs/FINAL-PROJECT-2026-07.md`): 4 588 собранных роликов-референсов,
159 источников, 18 утверждённых рецептов в 5 нишах, 87 сценариев, 567 прогонов в журнале,
1 688 тестов, 449 коммитов за 21 день. Верхние 12 звеньев конвейера из 15 работали на боевых
данных; нижнее звено (съёмка → публикация → обучение на своей статистике) не запускалось —
продюсер не был нанят, реальных публикаций ноль, все строки CF Published Reels помечены `demo`.
Петля обратной связи проверена слепым тестом на синтетических метриках (12 из 12, включая два
отрицательных контроля). 13.08.2026 завод поставлен на паузу решением владельца: все системные
таймеры выключены, данные не копятся (`AGENTS.md`, «Состояние на 14.09.2026»).
