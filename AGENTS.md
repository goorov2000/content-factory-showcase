# Content Factory — правила системы

## Что это
Intelligence-слой контент-завода. Runtime-сбор — Python: `cf collect
tiktok|instagram|snowball|performance` по systemd-таймерам (n8n-сбор списан
2026-07-24, `n8n/` — замороженный архив; инстанс n8n ждёт publish-звена этапа 6).
Агентный слой (Claude Code и Codex, см. «Совместимость агентов») = анализ паттернов,
формулы, генерация брифов, ревью брифов, eval, prompt proposals.

**Состояние на 14.09.2026.** Завод на паузе с 13.08: все 11 системных таймеров `cf-*` disabled,
данные не копятся, числа в Sheets заморожены; включает обратно только оператор
(`sudo systemctl enable --now …`). Карта документов и порядок чтения — `docs/README.md`.

## Железные правила
1. **Evidence-first.** Ни одного вывода без ссылок на данные (source_urls, метрики).
   Паттерн, формула или proposal без evidence не создаются.
2. **insufficient_data — честный ответ.** Если данных мало — статус `insufficient_data`
   плюс перечень того, чего не хватает. Никаких выводов «на глаз».
3. **Промпт меняется только машинно-проверенным путём** (редакция 2026-07-26,
   решение владельца). Черновик → зелёный чек-лист → запись версии в
   `prompt_versions` → git commit. Человек держит ВЕТО и откат, но читать текст
   промпта не обязан: за него это делают проверки (`cf apply-brief-prompt --check`).
   Красный чек-лист — единственное, что доходит до человека, и то одной строкой.
   Прежняя редакция требовала клика оператора на каждый промпт; её сняли, когда
   стало видно, что клик подменяет собой недостающую проверку, а не добавляет
   суждение: черновик 26.07 протух за час, и поймала это сверка со снапшотами.
   Ограничения остаются: агент не пишет в `prompts/**` напрямую (в Claude Code —
   deny-правила харнесса, в Codex — PreToolUse-guard из `.codex/hooks.json`) —
   только через аппликатор; правка ДЕЙСТВУЮЩЕГО промпта идёт
   кандидатом через A/B (`cf ab-plan`), а не заменой активной версии; auto-push
   запрещён. Рычаг возврата в ручной режим — `cf.config.json` →
   `gates.policy.<ворота> = "manual"`.
4. **Runtime-артефакты только в `agent-runtime/`** (не версионируется).
   Черновые выгрузки и разовые скрипты сессии — в `agent-runtime/scratch/<ГГГГ-ММ-ДД>/`, не в корень
   `agent-runtime/` (корень чистили дважды: 25.07 и 14.09); evidence, на которое ссылается версионируемый
   файл, — под датой в имени, иначе его перезапишут.
   Версионируются: `prompts/`, `formulas/`, `proposals/`, `schemas/`, `sources/`,
   `.claude/`, `.agents/`, `.codex/`.
5. **Секреты не коммитятся.** `secrets/` в `.gitignore`; перед коммитом работает pre-commit guard.
6. **Каждый запуск агента логируется** в CF Run Log — либо автоматически из CLI,
   либо командой `.venv/bin/python -m cf log-run ...` в конце работы агента.

## Инструменты
- CLI: `.venv/bin/python -m cf <command>` (консольный `cf` — только как `.venv/bin/cf`, в PATH
  systemd/шеллов его нет). **Справочник подкоманд, ключей `cf.config.json` и порогов конвейера —
  `docs/cf-cli.md`; абзац подкоманды читать до её запуска**: там то, чего нет в `--help`, —
  что пишется в Sheets, что платно, что правится только машиной.
- Каждый прогон — строка в Run Log (правило №6): `cf log-run ... --started-at ISO8601`
  (без флага длительность нулевая).
- Конфиг — `cf.config.json`; таксономия ниш — `prompts/agents/niche-taxonomy.json` (единственный
  источник истины); готовность темы к брифам — только `cf.dashboard.queues.prompt_state`.
- Руками не писать: `formulas/_approved/**` (иммутабельные снапшоты, пишет `cf approve-formula`),
  `sources/*.json` (только proposal + `cf apply-sources`), `.agents/skills/cf-*` (генерат
  `cf codex-sync`).
- Платные звенья — `collect`, `vision`, фан-аут ниш и конвейерные `/cf-*`: запускать только явно.

## Ворота конвейера (2026-07-26, авто-режим с вечера того же дня)
Порядок: сбор → разметка тем → анализ приёмов → черновики рецептов → **ворота:
одобрение рецептов** → черновик промпта темы → **ворота: включение промпта темы** →
сценарии → ревью → **ворота: одобрение сценариев** → съёмка → статистика.

**Кто их закрывает.** Двое первых ворот закрывает машина, третьи — человек.
Основание — не удобство, а компетенция: конечный пользователь завода это
SMM-продюсер, он эксперт по контенту и судит СЦЕНАРИЙ, а не рецепт, промпт и
покрытие. Плюс калибровка на 24 решениях оператора (26.07, воспроизводится
командой `cf gate-calibration`): 22 совпадения, 1 раз машина строже человека
(рецепт без расшифровок уходит к нему — качество не страдает, стоит одного
решения) и 1 пропуск — суждение о бизнес-контексте, которое закрывает
агент-судья, а не клик.
- **Рецепты** — `cf auto-approve-formula`: 12 детерминированных проверок
  (`--check` показывает их) плюс вердикт `formula-reviewer`. Красный чек-лист —
  рецепт остаётся черновиком и виден на воротах с причиной.
- **Промпт темы** — `cf apply-brief-prompt --auto`: семь отказов аппликатора плюс
  покрытие всех утверждённых рецептов и свежесть ссылок на снапшоты. Правка
  ДЕЙСТВУЮЩЕГО промпта авто-режимом не идёт никогда — только кандидатом в A/B.
- **Сценарии** — остаются за человеком: дальше идёт съёмка, то есть его время и
  деньги. `cf auto-approve` пред-фильтрует их вердиктом ревьюера (94% одобрений
  на 26.07 уже машинные), человек решает, что снимать. До него доходят только
  настоящие решения: забракованные ревьюером переписывает `brief-fixer` (шаг
  «Доработка сценариев», одна попытка на бриф), а упёршиеся в кап помечаются
  «отложено заводом» и возвращаются в игру сами (`cf retry-deferred`).
  С 04.08 к вердикту ревьюера добавлена арифметика — `cf.craftcheck`, пять
  детерминированных проверок ТЕКСТА сценария: незаполненные `[подстановки]`,
  самопротиворечие скрипта и капшена, ремарка вместо реплики в поле `hook`,
  непроизносимый тайминг (16 знаков/с) и лексический повтор одобренного брифа той
  же формулы за 30 дней. Основание — аудит 114 сценариев
  (`agent-runtime/analysis/2026-08-04-script-quality-audit.md`): семь проверок
  ревьюера смотрят на СООТВЕТСТВИЕ (снапшоту, референсам, нише, схеме) и ни одна
  не смотрела на текст, поэтому 8 смертельных дефектов из 12 прошли ворота.
  Пороги откалиброваны по двум единственным применениям нормы, которые в системе
  были (вердикты ревьюера 03.08), и держатся в одном месте — `src/cf/craftcheck.py`.
  Красный чек-лист оставляет бриф в pending: ручная кнопка продюсера работает
  всегда и зелёного не требует.
- **Правка действующего промпта темы** авто-режимом не заменяет активную версию
  никогда: `cf apply-prompt-candidate` ставит её КАНДИДАТОМ в A/B рядом с
  работающей (`cf.abtest.interleave_plan` чередует их между брифами), и вердикт
  выносит недельный eval. Промпт не утверждается — он выигрывает A/B.
- Политика каждых ворот — `cf.config.json` → `gates.policy.<ключ>`
  (`auto`|`manual`). Возврат в ручной режим стоит одной строки; ручная кнопка
  оператора работает всегда и НЕ требует зелёного чек-листа — иначе у человека не
  осталось бы способа расшить тему руками.
- Цена ошибки авто-решения ограничена конструкцией: плохой рецепт даёт
  `briefs_per_formula` сценариев, их бракует ревьюер, а `cf formula-guard` снимает
  рецепт с производства по 3 отказам из 5 — без единой строки performance.
- Журнал решений — `formulas/_decisions.jsonl` (append-only, версионируется): кто
  решил (`human`/`auto`), что и почему. Отказ человека помнится: авто-режим не
  возвращает отклонённый им рецепт следующей версией (`autogate.human_rejections`).
- Верх конвейера (шаги 1-4) не гейтится никогда: данные копятся, даже когда всё
  стоит на воротах.
- Ворота «Одобрение рецептов» держат ПО ТЕМЕ: блокирует только тема, у которой
  без решения нет ни одного утверждённого рецепта.
- Воркер с пустой очередью платного вызова не делает и пишет причину в ленту.
  Исключение — правило №2: если `prompt_versions` не прочитаны, воркер идёт как
  обычно (гасить производство по НЕпрочитанным данным нельзя).
- Единый источник очередей и ворот — `src/cf/dashboard/queues.py`. Новых
  предикатов «готова ли тема» не заводить: из-за трёх копий этого признака
  10 из 14 утверждённых рецептов молча не давали сценариев.
- Slash-команды: /cf-profile, /cf-analyze, /cf-formula, /cf-generate-briefs,
  /cf-review-brief, /cf-review-formula (судья рецептов перед машинным одобрением),
  /cf-propose-update, /cf-eval, /cf-status, /cf-classify-niche,
  /cf-tune-sources, /cf-niche-run (ядро фан-аута: профиль + анализ + черновики формул
  одной ниши за один прогон), /cf-write-brief-prompt (черновик промпта темы —
  зовётся воркером цикла и кнопкой ▶ на воротах). Канон каждой команды —
  `.claude/commands/<имя>.md`; в Codex те же команды зовутся скиллами `$cf-<имя>`
  (обёртки в `.agents/skills/`, генерят `cf codex-sync`, руками не правятся).
- Каталог `n8n/` — замороженный АРХИВ списанного n8n-сбора (2026-07-24):
  воркфлоу в живом n8n деактивированы, править/пушить их не нужно.
  История контура: docs/n8n-integration.md.

## Разработка завода (конвейер скиллов)
Не путать с конвейером контента выше: здесь про то, как чинится и растёт сам код.

Рабочий набор — скиллпак `mattpocock/skills` (состав и версии — `skills-lock.json`;
внешний реестр — skills.sh, установщика в репо нет, пак вендорится целиком; каталоги `.agents/skills/` и симлинки `.claude/skills/*`
версионируются вместе с ним, иначе на чистом клоне слэш-команды битые; Codex
читает `.agents/skills/` напрямую, симлинки ему не нужны).
Порядок: `/grill-me` → `/to-spec` → `/to-tickets` → `/implement` → `/code-review`.
Для интерфейса между `to-spec` и `to-tickets` добавляются `/design-an-interface`
и `/prototype`: спецификация экрана, которого никто не видел, фиксирует догадку,
а не решение. Крупный размытый замысел начинается с `/wayfinder`, старый код —
с `/improve-codebase-architecture`.

**Superpowers списан 2026-07-28.** Он проектировался под слабые модели: жёсткая
спецификация, план на 80–100K контекста и ревью после каждой таски держали в
рамках Sonnet 4.x. На сильной модели те же рамки дают тот же результат медленнее,
дороже и точностью ниже. Каталог `docs/superpowers/` — АРХИВ восьми планов
09–25.07: они остаются evidence по правилу №1, не переименовываются и не удаляются.

Тикеты скиллов живут в `docs/plans/<фича>/issues/NN-slug.md` — там же, где планы.
Отдельного `.scratch/` завод не заводит: три хранилища планов вместо одного
расходятся. Детали трекера — `docs/agents/issue-tracker.md`, роли триажа —
`docs/agents/triage-labels.md`, что читать до кода и каким словарём —
`docs/agents/domain.md`.

## Память агентов
`.claude/memory/MEMORY.md` — индекс: одна строка на файл памяти.
- Наблюдения анализа → `.claude/memory/patterns/{niche}-observations.md`
- Решения оператора → `.claude/memory/decisions/YYYY-MM-DD-<решение>.md`
- Инсайты eval → `.claude/memory/evaluations/YYYY-MM-DD-insights.md`
После записи файла памяти — обновить строку в MEMORY.md.

## Совместимость агентов (Claude Code + Codex)
- Канон правил — этот файл, `AGENTS.md` (его читают Codex и другие агенты
  стандарта agents.md); `CLAUDE.md` — симлинк на него для Claude Code. Держать
  файл меньше 32 KiB: Codex молча обрезает project-doc сверх лимита.
- Слэш-команды `.claude/commands/cf-*.md` — канон; их Codex-обёртки в
  `.agents/skills/cf-*/` — генерат `cf codex-sync` (install-agent и
  apply-agent-edit перегенерируют сами). Обёртки не правятся руками и зовутся
  только явно (`$cf-<имя>`): неявный вызов платных конвейерных команд по
  совпадению описания выключен в `.agents/skills/<имя>/agents/openai.yaml`.
- Крупный батч и параллельный разбор разрешено делить на подагентов (Codex — `spawn_agent`,
  Claude Code — Agent); каждый пишет свой фрагмент в `agent-runtime/`, сводку делает главный.
- Codex не видит `.claude/skills/**` и авто-память Claude Code: всё нужное обоим агентам лежит
  в репо. Вход в работу из Codex — `docs/codex-start.md`.
- Проектный слой Codex — `.codex/`: config.toml (сеть внутри песочницы — cf CLI
  ходит в Google Sheets), hooks.json + hooks/guard_protected_paths.py (зеркало
  deny-правил: prompts/**, .claude/commands/**, formulas/_approved/**),
  rules/cf.rules (git push — только с явным подтверждением, правило №3).
  Codex грузит слой только для trusted-проекта; command-хук дополнительно
  требует разового доверия через /hooks.
- Личный оверрайд инструкций — `AGENTS.override.md` (в .gitignore, Codex читает
  его ВМЕСТО AGENTS.md — не для постоянных правил).
- Подробности и приёмка — docs/codex.md.
