# Proposal: обязательный `cf log-run --status skipped` на путях «работы нет»

## Current version
- `prompts/agents/niche-classifier.md:17` — «Отбери строки с пустой niche. Таких нет →
  скажи об этом и остановись» (шаг `log-run` идёт позже и не достигается).
- `.claude/commands/cf-review-brief.md:9-10` — «для --pending — все с
  review_status=pending (таких нет → скажи об этом и остановись)» (лог — шаг 7,
  не достигается).
- `prompts/agents/brief-generator.md` — путь «approved-индекс пуст / все формулы
  под капом» не имеет явной инструкции лога (явный `log-run` есть только для
  путей 2а и падения ab-plan).

## Proposed changes
Во всех трёх местах заменить «скажи об этом и остановись» на:

```diff
-Таких нет → скажи об этом и остановись.
+Таких нет → залогируй холостой прогон и остановись:
+`.venv/bin/python -m cf log-run --agent <имя-агента> --status skipped
+ --input-summary "нет работы: <что именно пусто>"`.
```

(для brief-generator — добавить тот же шаг на путь «индекс пуст / все формулы
пропущены», агент `brief-generator`).

## Evidence
- **Правило №6 CLAUDE.md**: «Каждый запуск агента логируется в CF Run Log» — без
  исключений для холостых прогонов. `src/cf/runlog.py:5-7` прямо предусматривает
  статус `skipped`: «прогон не состоялся осознанно… след в Run Log обязателен
  (железное правило №6)». Текущие промпты этому правилу противоречат.
- **Инцидент 2026-07-24**: заблокированные permission-системой агенты фан-аута
  «вежливо» отчитались текстом и вышли кодом 0 — звено dashboard-factory легло в
  Run Log как success (Run Log 42961736a490). После фикса раннер требует след
  агента в Run Log (`StageRunner._agent_logged`); пока промпты не логируют
  холостые пути, тихие дни будут давать ложный warn «прогон холостой или лог
  пропущен» (подтверждено адверсариальным ревью фикса, находка high).
- Прецедент страховки в коде: `src/cf/cli.py` сам дописывает строку apply-niches
  «на случай пропуска шага cf log-run в промпте» — контракт уже считается
  обязательным.

## Confidence
high — правка синхронизирует промпты с уже действующим правилом №6 и снимает
единственный известный источник ложных срабатываний детектора холостых прогонов.

## Risks
+1 вызов CLI на холостой прогон (незначительно). Строк skipped в Run Log станет
больше — это ожидаемо и полезно: «тишина» и «блокировка» перестают быть
неразличимыми. Применение: правки файлов промптов руками оператора (deny-правила
запрещают агентам писать в `prompts/agents/**` и `.claude/commands/**`) +
`cf log-prompt-version` при необходимости.
