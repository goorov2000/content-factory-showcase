# Proposal: `cf log-run --started-at` — в Run Log должна попадать длительность прогона

> **Статус реализации на 2026-07-26.** Кодовая половина применена: флаг
> `--started-at` у `cf log-run` есть, момент старта пробрасывается из всех 18
> внутренних вызовов CLI (штамп процесса в `main()`), из четырёх модулей сбора
> (`_iso_seconds(collected)`) и из звеньев дашборда (`StageRunner._stage_started`).
> Отклонение от текста ниже одно и осознанное: битое значение флага НЕ роняет
> команду. Argparse-exit означал бы, что строки в Run Log нет вовсе, а
> `StageRunner._agent_logged` объявил бы прогон ниши холостым и перевёл её в
> error — железное правило №6 старше точности метрики, поэтому мусор даёт
> предупреждение в stderr и строку с нулевой длительностью.
> **Промптовая половина применена 2026-07-26** по решению оператора. Отклонения от
> списка выше: `prompts/agents/niche-pipeline.md` не существует (звено управляется
> командой `.claude/commands/cf-niche-run.md`), а `prompts/agents/brief-reviewer.md`
> и `prompts/agents/eval-agent.md` вызова log-run не содержат вовсе. Зато мест с
> log-run оказалось не 8, а 15 — правило «единая формулировка для всех агентов»
> применено ко всем: 5 промптов агентов и 10 слэш-команд. Вместо правки каждого
> вызова в файл добавлена одна директива «запомни время старта и передавай его
> КАЖДОМУ вызову log-run» — эквивалентно по смыслу и не ломает обёрнутые команды.

## Current version

`cf log-run` не принимает время старта, поэтому `src/cf/runlog.py:23` ставит
`started_at = completed_at` — момент записи строки:

```python
completed = now_iso()
row = {
    ...
    "started_at": started_at or completed,   # параметр есть, но его никто не передаёт
    "completed_at": completed,
```

Промпты агентов зовут лог последним шагом, без времени старта. Пример
(`prompts/agents/niche-classifier.md`, шаг логирования):

```
`.venv/bin/python -m cf log-run --agent niche-classifier --status success
 --input "<что размечено>"`
```

## Proposed changes

1. **CLI** (`src/cf/cli.py`, `cmd_log_run`): добавить флаг `--started-at ISO8601`,
   пробросить в `runlog.log_run(started_at=...)`. Значение мимо ISO — ошибка
   аргумента, а не молчаливая подмена на «сейчас» (иначе баг вернётся тихо).
2. **Промпты агентов**: первым шагом работы зафиксировать время старта, последним —
   передать его в лог. Единая формулировка для всех агентов:

```diff
+Перед началом работы запомни время старта:
+`date -u +%Y-%m-%dT%H:%M:%S+00:00`
 ...
-`.venv/bin/python -m cf log-run --agent <имя> --status <статус> --input "<...>"`
+`.venv/bin/python -m cf log-run --agent <имя> --status <статус> --input "<...>"
+ --started-at <запомненное время>`
```

Затрагиваемые промпты: `prompts/agents/niche-classifier.md`,
`prompts/agents/niche-pipeline.md`, `prompts/agents/brief-generator.md`,
`prompts/agents/brief-reviewer.md`, команды `.claude/commands/cf-classify-niche.md`,
`.claude/commands/cf-review-brief.md`, `.claude/commands/cf-eval.md`,
`.claude/commands/cf-tune-sources.md`.

## Evidence

- **Все длительности в логе нулевые.** Чтение боевого Run Log 2026-07-25 (211
  строк): у каждой строки `started_at == completed_at`. Примеры `niche-classifier`:
  `2026-07-25T03:44:29 → 2026-07-25T03:44:29`, `04:45:44 → 04:45:44`,
  `04:50:39 → 04:50:39`. Итог: `median_duration(rows, agent)` возвращает `0.0`
  для всех агентов конвейера (проверено на niche-classifier, niche-pipeline,
  brief-generator, brief-reviewer).
- **Из-за этого врал прогресс.** `StageRunner._stage_etas` брал медиану из Run Log,
  получал `0` (ложь) и падал на `DEFAULT_ETA_SEC = 90`. Кривая полоски обещала
  полторы минуты шагу, который реально шёл 18:03 (прогон 2026-07-25 07:33 → 07:51,
  замер раннера 1082.8 с), и упиралась в свой кэп через ~4 минуты. Жалоба
  оператора: «разметка должна занимать 18 минут?» — сам вопрос возник потому, что
  шкала обещала другое.
- **Обходной путь уже сделан, но он локальный.** Раннер дашборда теперь меряет
  длительности сам (`agent-runtime/reports/step-durations.json`, коммит
  «полоску больше не отталкивает назад…»). Это закрывает прогресс-бар, но не
  закрывает Run Log: у ручных прогонов агентов (не через дашборд) длительности
  по-прежнему нет, и `cf eval` / «История задач» не могут ответить, сколько
  занимает работа и растёт ли это время.
- **Схема к этому готова.** `runlog.log_run` уже принимает `started_at`
  (`src/cf/runlog.py:15`), колонка `started_at` в CF Run Log существует и
  заполняется — меняется только источник значения.

## Confidence

high — факт проверяется одним чтением Run Log (все 211 строк нулевой длины), схема
уже принимает `started_at`, а последствие пустой медианы наблюдалось на живом
прогоне. Правка аддитивна: без флага поведение прежнее.

## Risks

- Агент может забыть зафиксировать старт → `--started-at` не передан → поведение
  ровно как сейчас (метка = момент записи). Деградация мягкая, ничего не ломается.
- Часы агента и хоста — одни и те же (агент работает на том же VPS), расхождения
  таймзон нет: обе метки в UTC через `now_iso()` / `date -u`.
- Строки старого формата в Run Log остаются нулевыми: `median_duration` их просто
  отбрасывает как нулевые (0 — falsy), медиана поедет только на новых прогонах.

## Rollback

Убрать `--started-at` из промптов (флаг в CLI можно оставить — он опционален).
