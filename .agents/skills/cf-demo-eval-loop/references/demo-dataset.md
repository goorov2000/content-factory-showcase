# Состав демо-данных и ключ ответов

Цифры подобраны так, что правильный ответ системы известен заранее и
арифметически неизбежен. Проверять расчёт при любом изменении состава: пороги
гвардии считаются от ОБЩЕЙ медианы всех замеров, поэтому смена одной строки
двигает вердикт по всем рецептам.

## 1. Откуда брать сценарии

Настоящие утверждённые сценарии из свежего снимка:

```bash
.venv/bin/python - <<'PY'
import json, collections, glob
path = sorted(glob.glob('agent-runtime/backups/*-briefs.jsonl'))[-1]
rows = [json.loads(l) for l in open(path)]
appr = [r for r in rows if r.get('review_status') == 'approved']
print(path, '| approved:', len(appr))
print(collections.Counter(r['formula_id'] for r in appr))
PY
```

Выдуманные `brief_id` использовать нельзя: без связки с брифом у замера пустой
`formula_id`, и ни гвардия, ни когорты не работают.

## 2. Состав (35 роликов, 37 замеров)

Тема мужские-образы: активная версия промпта `v2`, кандидат A/B — `v4`.
Остальные темы: `v1`.

| Рецепт | Роликов | Версия | Просмотры | Медиана | Роль в испытании |
|---|---|---|---|---|---|
| `short-styling-idea-reel` | 10 | 5 × `v2` / 5 × `v4` | v2: 4200, 4800, 5100, 5600, 6300 · v4: 12400, 13900, 14600, 15800, 17200 | v2: 5100 · v4: 14600 | **ось A/B** — вердикт «v4 сильнее» |
| `store-native-skit` | 4 | `v1` | 640, 710, 820, 900 | 765 | **жертва P5.10** — авто-пауза |
| `expert-item-breakdown` | 5 | `v1` | 6400, 7300, 8100, 8600, 9200 | 8100 | фон |
| `mass-brand-hot-take` | 5 | `v1` | 1200, 9800, 10400, 11200, 12100 | 10400 | фон + **провальный ролик** (1200) для атрибуции |
| `brand-list-quick-positioning` | 5 | `v1` | 7600, 8800, 9400, 9900, 10600 | 9400 | фон |
| `grwm-interactive-frame` | 4 | 2 × `v2` / 2 × `v4` | 5800, 6200, 6600, 7100 | 6400 | **контроль:** когорта тонкая → `insufficient_data` |
| `color-upgrade-ladder` | 2 | `v1` | 680, 740 | 710 | **контроль:** выборка мала → НЕ паузить |

**Арифметика гвардии.** Общая медиана 35 замеров = **7300**, порог паузы =
0.5 × 7300 = **3650**, минимум замеров = 3.

- `store-native-skit`: 765 < 3650 и 4 ≥ 3 → **пауза**;
- `color-upgrade-ladder`: 710 < 3650, но 2 < 3 → **не паузить**;
- `mass-brand-hot-take`: медиана 10400 > 3650 → не паузить, несмотря на один
  провальный ролик (гвардия не должна реагировать на одиночный флоп);
- `short-styling-idea-reel`: гвардия смотрит на рецепт целиком (медиана 9350),
  слабость версии `v2` рецепт не топит — это разбирает eval, а не гвардия.

## 3. Даты

Окно публикации: 2026-07-08 … 2026-07-19. `measured_at = published_at + 7 дней`
(точное попадание в цель дедупа). Всё внутри 28-дневного окна гвардии.

**Версии чередуются по дням, а не блоками** — иначе окна не пересекутся и
A/B-вердикта не будет вовсе:

```
07-08 v2 · 07-09 v4 · 07-10 v2 · 07-11 v4 · 07-12 v2
07-13 v4 · 07-14 v2 · 07-15 v4 · 07-16 v2 · 07-17 v4
```

Окно `v2` = [07-08, 07-16], окно `v4` = [07-09, 07-17] — пересекаются, значит
одна параллельная когорта. То же чередование у `grwm-interactive-frame`.

Остальные рецепты — любые даты внутри окна.

**Дедуп:** двум роликам (один `short-styling-idea-reel` `v4`, один
`expert-item-breakdown`) добавить ВТОРОЙ замер на 3-й день после публикации с
меньшими просмотрами. Всего строк замеров 37, в датасете обязано остаться 35 —
берётся замер, ближайший к 7-му дню.

## 4. Прочие поля

- `platform` — из брифа (там `tiktok`);
- `post_url` — `https://demo.invalid/tiktok/DEMO-<slug>`. Зона `.invalid`
  зарезервирована и не резолвится никогда: второй предохранитель на случай, если
  `status` кто-то поправит на `published`;
- `hours_since_publish` = 168 для семидневного замера, 72 для трёхдневного;
- `likes/comments/shares/saves` — правдоподобные доли просмотров, чтобы
  `er` попадал в 0.05–0.12; `er = (likes+comments+shares+saves)/views`,
  `views_per_hour = views / hours_since_publish` — считать, а не выдумывать
  (иначе витрины покажут несогласованные числа);
- `eval_notes` = `collection_status=metrics_collected; DEMO`.

## 5. Формат `agent-runtime/demo/plan.json`

```json
{
  "created_at": "2026-07-28",
  "note": "DEMO eval-loop, данные фиктивные, стираются командой cf demo-wipe",
  "reels": [
    {
      "slug": "ssir-01",
      "brief_id": "b-short-styling-idea-reel-20260714-weekrotation",
      "formula_id": "short-styling-idea-reel",
      "prompt_version": "v2",
      "platform": "tiktok",
      "published_at": "2026-07-08T09:00:00+00:00",
      "measurements": [
        {"days_after": 7, "views": 4200, "likes": 340, "comments": 21, "shares": 33, "saves": 52}
      ]
    }
  ]
}
```

`formula_id` в плане — для читаемости и самопроверки: сеялка обязана сверить его
с `formula_id` настоящего брифа и отказаться при расхождении.

## 6. Шаблон `agent-runtime/demo/answer-key.md`

Пишется ДО прогона. Формулировки проверяемые — «рецепт X снят с производства», а
не «система заметит проблему».

```markdown
# Ключ ответов — DEMO eval-loop <дата>

Данные фиктивные. Правильные выводы известны заранее; eval-агент их не видел.

## Система ОБЯЗАНА сказать
1. A/B темы мужские-образы: версия v4 сильнее v2 — медиана 14600 против 5100
   (≈2.9×), обе когорты по 5 замеров, вердикт допустим.
2. Рецепт store-native-skit провален у аудитории: медиана 765 при общей 7300 —
   снят с производства авто-паузой (окно 28 дн.).
3. Провальный ролик: <reel_id> рецепта mass-brand-hot-take — 1200 просмотров при
   медиане своей версии 10400 (0.12×); назван в атрибуции.
4. Темп производства: <N> роликов за окно при цели 70 в неделю.

## Система ОБЯЗАНА промолчать (insufficient_data)
5. grwm-interactive-frame: по 2 замера на v2 и v4 — вердикт по версиям не
   выносится, перечислено, каких замеров не хватает.
6. color-upgrade-ladder: 2 замера, ниже порога 3 — рецепт НЕ ставится на паузу,
   несмотря на низкие просмотры.
7. Датасет содержит 35 замеров, а не 37: у двух роликов по два замера, дедуп
   оставляет ближайший к 7-му дню.

## Система НЕ ДОЛЖНА
8. Ставить на паузу mass-brand-hot-take из-за одного провального ролика.
9. Выносить вердикт по версиям рецептов тем, где версия одна.
10. Называть демо-инсайты знанием о нише или предлагать применить proposal.

## Сверка
| # | Ожидание | Что сказала система | Совпало |
|---|---|---|---|
```

## 7. Отчёт по результату

В отчёт владельцу идут: заполненная таблица сверки, список расхождений с
разобранной причиной, подтверждение стирания. Расхождение — не провал сессии, а
её главный результат: ради этого испытание и ставится, пока цена ошибки нулевая.
