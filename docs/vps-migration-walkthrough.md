# Переезд CF на VPS — пошаговый гайд для чайников

Это расшифровка [vps-migration-guide.md](vps-migration-guide.md) до уровня
«какую кнопку нажать и что появится на экране». План и «зачем» — там,
здесь — только «как».

> **Статус (2026-07-24): миграция выполнена.** Этапы 0–5 закрыты, таймеры CF
> включены, идёт неделя наблюдения. Документ сохранён как справочник на
> случай настройки с нуля — **на живом сервере эти шаги повторять не нужно**:
> повторный прогон перезапишет рабочие ключи и секреты (см. предупреждения
> в шагах 12–13).
>
> Фактические параметры боевого сервера (план изначально писался под Beget,
> но VPS взят другой): адрес **<VPS_IP>** (`cf.example.com`), рабочий
> пользователь `<user>`, репозиторий в `~/projects/CF`, секреты в
> `~/.cf/secrets/`. Домен `n8n.example.com` указывает на **старый удалённый
> хостинг n8n** и к этому серверу отношения не имеет.

Обозначения:

- `ноутбук>` — команда вводится в PowerShell на твоём ноутбуке;
- `сервер>` — команда вводится в терминале, когда ты уже зашёл на сервер
  (после `ssh`);
- 📺 — что примерно увидишь на экране;
- ✅ — как проверить, что шаг удался.

Пароли и коды в терминале **вводятся невидимо** — курсор не движется,
звёздочек нет. Это нормально: печатай и жми Enter.

## Часть А — базовый доступ к серверу (выполнена 2026-07-23)

### Шаг 1. Открыть терминал на ноутбуке

Нажми `Win`, набери `PowerShell`, Enter. Синее/чёрное окно с мигающим
курсором — это оно.

### Шаг 2. Первый вход на сервер (по паролю)

```powershell
ssh <user>@<VPS_IP>
```

(На свежем сервере учётка может называться иначе — смотри письмо хостера;
на боевом сервере CF это `<user>`.)

📺 При самом первом подключении спросит:

```
The authenticity of host '<VPS_IP>' can't be established.
... Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

Набери `yes`, Enter. Дальше `<user>@<VPS_IP>'s password:` — введи пароль
пользователя из данных хостера (невидимо), Enter.

✅ Строка приглашения сменилась на что-то вроде `<user>@vm-mini:~$` — ты
внутри сервера. Всё, что теперь набираешь, выполняется **на сервере**.

Выйти обратно на ноутбук: команда `exit`.

### Шаг 3. Создать SSH-ключ на ноутбуке

Убедись, что ты **на ноутбуке** (вышел через `exit`; приглашение —
`PS C:\...>`).

```powershell
ssh-keygen -t ed25519 -C "operator@laptop"
```

📺 Задаст три вопроса (куда сохранить, пароль на ключ, повтор пароля) — на
все три просто жми **Enter**.

✅ В конце нарисует «картинку» ключа (randomart). Файлы появились в
`C:\Users\<твой юзер>\.ssh\`: `id_ed25519` (секретный — никому) и
`id_ed25519.pub` (публичный).

### Шаг 4. Положить публичный ключ на сервер

Одной командой с ноутбука (спросит пароль root — в последний раз):

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh <user>@<VPS_IP> "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

✅ Проверка: `ssh <user>@<VPS_IP>` — должен пустить **без вопроса о
пароле**. Если пароль всё ещё спрашивает — напиши мне, разберём.

### Шаг 5. Короткое имя для сервера

```powershell
notepad "$env:USERPROFILE\.ssh\config"
```

📺 Блокнот спросит «Создать файл?» — Да. Вставь ровно это и сохрани
(Ctrl+S), закрой:

```
Host cf-vps
    HostName <VPS_IP>
    User <user>
    IdentityFile ~/.ssh/id_ed25519
```

✅ `ssh cf-vps` в PowerShell — заходит на сервер без пароля.

### Шаг 6. Подключить VS Code к серверу

1. VS Code → иконка кубиков слева (Extensions) → в поиске `Remote-SSH` →
   у расширения от **Microsoft** нажми Install.
2. Нажми `F1` → набери `remote-ssh` → выбери **Remote-SSH: Connect to
   Host...** → в списке будет `cf-vps` → кликни.
3. Откроется новое окно; на вопрос про платформу сервера выбери **Linux**.
   Полминуты установки — и внизу слева появится зелёная плашка
   `SSH: cf-vps`.

✅ Меню Terminal → New Terminal (или `` Ctrl+` ``) — терминал в этом окне
открывается **уже на сервере** (приглашение `root@...`). Через File → Open
Folder можно открыть любую папку сервера, например `/root`.

### Шаг 7. Выключить вход по паролю (защита от ботов)

⚠️ Делай только после того, как шаг 4 точно работает. И держи **второе окно
терминала с уже открытой сессией на сервер** — если что-то пойдёт не так,
через него починим.

Ловушка Ubuntu: в начале `/etc/ssh/sshd_config` стоит строка
`Include /etc/ssh/sshd_config.d/*.conf`, и значения из этих файлов
**побеждают** основной файл (sshd берёт первое встреченное значение).
Облачный образ кладёт туда `50-cloud-init.conf` с
`PasswordAuthentication yes`, поэтому правка одного лишь `sshd_config`
ничего не меняет — править нужно именно этот drop-in.

На сервере (три команды; спросят пароль sudo):

```bash
sudo sh -c 'printf "PasswordAuthentication no\n" > /etc/ssh/sshd_config.d/50-cloud-init.conf'
sudo sshd -t
sudo systemctl reload ssh
```

`sshd -t` молчит — конфиг корректен; если ругается — ничего не перезапускай
и разбирайся по сообщению.

✅ Проверяй **эффективную** настройку, а не содержимое файла:

```bash
sudo sshd -T | grep -i passwordauthentication
```

— должно напечатать `passwordauthentication no`. И из нового окна PowerShell:
`ssh cf-vps` — пускает по ключу как раньше. (Если бы ключ сломался, писало
бы `Permission denied (publickey)` — тогда чини из оставшегося открытого
окна: верни в drop-in `yes` и снова `sudo systemctl reload ssh`.)

### Шаг 8. Проверить, что сервер потянет

На сервере:

```bash
free -h && df -h / && nproc
```

📺 Пример:

```
               total   used   free ...
Mem:           7.8Gi  1.2Gi  5.9Gi
...
/dev/vda1       50G    12G    38G  25% /
4
```

✅ Смотри `Mem: total` — нужно **4Gi или больше** (claude CLI требует 4 ГБ,
плюс запас под дашборд и сборы). Диск: свободно хотя бы 10G. Если памяти
меньше — в панели хостера подними тариф (память/ядра обычно меняются без
пересоздания сервера), потом продолжай.

### Шаг 9. Apify-токен → на сервер

1. В браузере: [console.apify.com](https://console.apify.com) → залогинься →
   слева внизу **Settings** → вкладка **API & Integrations** (или
   **API tokens**) → скопируй Personal API token (или Create new token).
2. Сохрани его в менеджер паролей.
3. На сервере:

```bash
mkdir -p ~/.cf/secrets && chmod 700 ~/.cf/secrets
nano ~/.cf/secrets/apify-token.txt
```

📺 Пустой редактор. Вставь токен (правая кнопка мыши = вставка в терминале),
одна строка, без пробелов. `Ctrl+O`, Enter, `Ctrl+X`. Затем:

```bash
chmod 600 ~/.cf/secrets/apify-token.txt
```

✅ `cat ~/.cf/secrets/apify-token.txt` — печатает твой токен одной строкой.

### Шаг 10. Сказать мне «токен на месте»

На этом часть А закончена. Дальше работаю я (этап 2 — порт кода, на
ноутбуке), тебе останется ревью. **Ничего на сервере больше не трогаем**,
n8n продолжает работать как работал.

## Часть Б — во время деплоя (этап 3; выполнена 2026-07-24)

Эти шаги делаются, когда порт кода готов и я скажу «деплоимся». Порядок
внутри части Б не важен, можно заранее.

### Шаг 11. DNS-запись для дашборда

> На боевом сервере уже сделано: `cf.example.com` → <VPS_IP>.

В панели DNS-провайдера, где заведён домен `example.com`:

- тип записи: **A**
- имя/поддомен: `cf`
- значение: IP сервера — `<VPS_IP>` (на сервере его же показывает
  команда `curl ifconfig.me`).

✅ Через 5–30 минут `ping cf.example.com` с ноутбука показывает IP
сервера.

### Шаг 12. Telegram-бот для уведомлений

> ⚠️ На боевом сервере бот уже создан и подключён: **<BOT_USERNAME>**, его токен
> и chat_id лежат в `~/.cf/secrets/telegram-token.txt` и
> `telegram-chat-id.txt` (e2e через `cf.notify` подтверждён).
> **Не перезаписывай эти файлы** — уведомления молча переключатся на
> неподключённого бота, и алерты недели наблюдения пропадут. Шаг нужен
> только при настройке с нуля.

1. В Telegram найди **@BotFather** → `/newbot` → придумай имя (например
   `CF Notify`) и юзернейм (например `cf_jelapeche_bot`).
2. BotFather пришлёт **токен** вида `1234567890:AAE...` — сохрани в менеджер
   паролей.
3. Открой чат со своим новым ботом и напиши ему любое сообщение (это нужно,
   чтобы бот получил право писать тебе).
4. Узнай свой chat_id — на сервере. Токен **нельзя вставлять прямо в
   команду**: команда целиком сохранится в историю терминала
   (`~/.bash_history`) вместе с токеном. Сначала положи токен в переменную:

```bash
read -rs TOKEN   # вставь токен (невидимо) и нажми Enter
curl -s "https://api.telegram.org/bot${TOKEN}/getUpdates"
```

📺 В ответе-JSON найди `"chat":{"id":123456789,...}` — это число и есть
chat_id.

5. Положи оба значения на сервер:

```bash
nano ~/.cf/secrets/telegram-token.txt    # вставить токен
nano ~/.cf/secrets/telegram-chat-id.txt  # вставить chat_id
chmod 600 ~/.cf/secrets/telegram-*.txt
```

### Шаг 13. Deploy-ключ GitHub

> ⚠️ На боевом сервере ключ уже создан и добавлен в GitHub (origin на ssh,
> пуши работают). Если `ls ~/.ssh/github_deploy` показывает файл — шаг
> пропусти. Ответ `y` на вопрос ssh-keygen «Overwrite?» сломает рабочий
> деплой: на GitHub останется старый публичный ключ, и пуши упадут с
> `Permission denied`.

На сервере:

```bash
ssh-keygen -t ed25519 -C "cf-vps-deploy" -f ~/.ssh/github_deploy
cat ~/.ssh/github_deploy.pub
```

📺 На оба вопроса про passphrase — просто **Enter** (пустая): ключом
пользуется автоматика (git pull/push по таймерам), ключ с passphrase
повесит её навсегда. `cat` напечатает строку, начинающуюся с
`ssh-ed25519 ...` — скопируй её целиком. В браузере: GitHub → репозиторий
`content-factory` → **Settings** → **Deploy keys** → **Add deploy key** →
вставь, поставь галку **Allow write access**, сохрани.

### Шаг 14. service-account.json на сервер

С ноутбука (файл гугл-таблиц, который сейчас лежит у CF на ноутбуке;
подставь свой путь):

```powershell
scp "C:\путь\к\service-account.json" cf-vps:~/.cf/secrets/service-account.json
ssh cf-vps "chmod 600 ~/.cf/secrets/service-account.json"
```

✅ На сервере `ls -l ~/.cf/secrets/` — файл в списке, права `-rw-------`
(без chmod scp оставит файл читаемым всем пользователям сервера, а это
ключ от гугл-таблиц).

### Шаг 15. Установить claude CLI и войти в подписку

На сервере:

```bash
curl -fsSL https://claude.ai/install.sh | bash
exec bash   # перезапуск оболочки — без этого команда claude ещё не в PATH
claude --version
claude
```

📺 При первом запуске `claude` покажет **ссылку и одноразовый код**. Ссылку
открой в браузере на ноутбуке, войди в аккаунт своей подписки Claude,
подтверди — код вставь обратно в терминал сервера. Логин запоминается,
повторно входить не нужно.

✅ `claude` запускается и отвечает без просьбы залогиниться.

Остальное в этапе 3 (git-клон, systemd-сервис, Caddy, таймеры, deploy.sh) —
готовлю я, тебе пришлю готовые команды «вставь и нажми Enter» по ходу.

   n8n снова вкл, минуты.

   команде.

## Если что-то пошло не так

| Симптом | Что это значит | Что делать |
| --- | --- | --- |
| `ssh: connect to host ... port 22: Connection timed out` | Сервер недоступен или сеть | Проверь интернет; в панели хостера посмотри, что VPS запущен |
| `Permission denied (publickey)` | Сервер не принял ключ, а пароль уже выключен | Зайди через оставшуюся открытую сессию и верни `PasswordAuthentication yes` в `/etc/ssh/sshd_config.d/50-cloud-init.conf` (шаг 7), напиши мне |
| Пароль спрашивает после шага 4 | Ключ не скопировался | Повтори шаг 4, проверь, что команда была одной строкой |
| `Host key verification failed` | Сервер переустанавливали, отпечаток сменился | Напиши мне — удалим старую строку из `known_hosts` |
| В nano всё сломал | — | `Ctrl+X`, на вопрос о сохранении ответь `N` — файл останется как был |
| Терминал «завис» после закрытия ноутбука | SSH-сессия оборвалась | Просто зайди заново `ssh cf-vps`; долгие процессы для того и запускаем в tmux/systemd |

Любой другой непонятный текст на экране — копируй целиком и присылай мне,
не гадай.
