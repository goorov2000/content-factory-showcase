# Конвейер формул: фан-аут анализа, очередь одобрения, генерация вширь

Дата: 2026-07-15. Статус: согласовано с оператором (брейншторм, вариант B).

## Цель

Завод должен выдавать **~70 одобренных брифов в неделю** к августу, чтобы прод
занимался только съёмкой. Сейчас: 1 формула, 1 ниша, ~6 брифов/нед, каждый бриф
одобряется вручную. Узкое место — не сбор (1600 raw) и не генерация, а
однопоточное производство формул и ручной гейт на каждом брифе.

**Ramp-up (ожидание, не провал):** первая неделя даст ~8–12 формул из TikTok-ниш
и ~30–40 брифов/нед. По Instagram (177 строк на все ниши) почти везде будет
insufficient_data. До 70 доезжаем после докачки IG и новых ниш из «other».

## Решения оператора

1. **Гейт переезжает с брифов на формулы.** Оператор утверждает формулы (редко,
   вдумчиво); брифы по утверждённой формуле с recommend ревьюера одобряются
   автоматически. Страховка — отзыв постфактум, не карантин.
2. **Классификатор может предлагать новые ниши** из кластеров «other» — вводятся
   только после одобрения оператора.
3. **Фан-аут по всем нишам с материалом**, включая тематически смежные
   (маркетплейсы, женская-мода…): формула — это приём подачи, не тема; приём
   переносится на мужскую одежду JLP.
4. Оркестратор — **Python-раннер дашборда** (вариант B): отдельный короткий
   headless-прогон на нишу, пул воркеров, а не один большой агент-дирижёр.

## Архитектура

### Фан-аут (звено «Контент-завод», режим конвейера формул)

```
▶ плитка → раннер:
  1. классификация новых строк (пустые niche) — /cf-classify-niche
  2. очередь ниш = ниши, где на платформе >= 12 строк с views >= 1000,
     МИНУС ниши, уже анализированные, у которых материал с тех пор
     вырос менее чем в 1.5 раза (перерасход впустую)
  3. пул из workers (конфиг dashboard.fanout.workers, дефолт 2):
     одна ниша = один headless-прогон: профиль → анализ → черновики формул
  4. по завершении всех ниш: генерация брифов по approved-формулам → авто-ревью
  5. git-коммит артефактов делает ТОЛЬКО раннер в конце прогона
```

- Плитка показывает живой прогресс: «ниши 4/9 · формул 6 · брифов 12».
- Падение одной ниши не валит прогон: ниша → warn в отчёте звена, ретрай
  кнопкой по одной нише. Итог прогона — сводка по всем нишам.
- Запуски логируются в CF Run Log (агенты сами + `dashboard-fanout`).

### Механика — в CLI, смысл — агенту (урок падения 2026-07-15)

Headless-права разрешают только `python -m cf`; квартильный расчёт в агенте
уже падал. Всю арифметику забираем в детерминированные cf-команды:

- **`cf analyze-batch <tab> --niche X`** — дедуп, порог views>=1000, квартили,
  winners/losers, same-account пары (метод v2 целиком) → машинный отчёт JSON.
  Агент (pattern-analyzer) получает готовые числа и делает только смысловую
  часть: формулировки паттернов, верификация evidence по транскриптам.
- **`cf cluster-other <tab>`** — TF-IDF/группировка «other» → компактные
  кластеры (30+ роликов) с примерами капшенов. Агент (niche-classifier) только
  называет кластеры и формирует предложения ниш. 700 сырых строк в контекст
  агента не загружаются никогда.

### Статусы формул и очередь одобрения

- В JSON формулы добавляются поля `status: proposed | approved | paused |
  rejected` и `status_reason`. Фан-аут пишет `proposed`.
- `formulas/_approved/index.json` — только approved (как сейчас); brief-generator
  читает только его. Это и есть гейт.
- **Лаборатория → вкладка «Формулы»**: карточка = имя, ниша, хук, evidence
  (avg views/ER, раскрываемые референсы), кнопки «Утвердить / В паузу /
  Отклонить». Кнопка делает то же, что approve-formula: правит status, index,
  пишет decision-файл в `.claude/memory/decisions/`, коммитит.
- **Предложения новых ниш** — карточки в той же очереди (бейдж «новая ниша»):
  «Принять нишу» → таксономия обновляется (+decision), кластер
  переклассифицируется, ниша попадает в следующий прогон анализа; «Отклонить» →
  кластер помечен, больше не предлагается. Не легло в кластеры — остаётся в
  «other» как честный осадок.

### Генерация вширь и авто-одобрение

- Brief-generator за прогон: до N брифов на каждую approved-формулу
  (конфиг `dashboard.fanout.briefs_per_formula`, дефолт 2) с ротацией
  `tested_variable` — брифы одной формулы не клоны.
- **Авто-approved ставит пайплайн, не ревьюер** (правило «ревьюер не ставит
  approved» сохраняется). Условия — все сразу: формула approved, промпт ниши
  активен, вердикт ревьюера recommend. Иначе бриф остаётся pending/rejected.
- Дедуп-правило «один pending на формулу» заменяется капом: не более 5
  approved-брифов на формулу за последние 7 дней (продакшн-статуса «снят»
  пока нет — это спека августа).
- **Страховки:**
  - на «Брифах» — лента свежеодобренных с бейджем «авто», отзыв существующей
    кнопкой «↺ Отменить решение» до съёмки;
  - **авто-пауза формулы**: >= 3 reject из последних 5 брифов формулы →
    `status: paused` + заметка на дашборде; снятие с паузы — кнопкой;
  - происхождение брифа («почему этот бриф») работает и для авто.

## Данные и отказоустойчивость

- Решения и артефакты формул живут в репо (`formulas/`), очередь на дашборде
  читается с диска (как lab_context сейчас). Sheets — брифы и Run Log, без
  новых вкладок.
- Параллельные воркеры не делают git-операций и пишут в непересекающиеся пути
  (каждый — своя ниша). Append в Run Log конкурентно-безопасен (gspread append).
- Сбой чтения/агрегации сводки не меняет результат звена (паттерн best-effort
  как в _factory_ops_detail).
- Тесты: оркестратор (очередь ниш, пул, агрегация, деградации), CLI-команды
  analyze-batch/cluster-other (фикстуры с известными квартилями/кластерами),
  очередь одобрения (роуты + шаблоны), авто-approve (все комбинации условий),
  авто-пауза. headless-вызовы мокаются через run_command (текущий паттерн).

## Вне скоупа

- Перекос источников (TikTok 1422 / IG 177) — существующий `/cf-tune-sources`,
  запустить после стабилизации таксономии; стройки не требует.
- Продакшн-статус брифа («снят/в производстве») и публикация — август.
- Fake-данные для eval-петли — отдельная задача, позже.
- publish-воркфлоу n8n, этап 3 (чат с Клодом) — прежние отдельные планы.

## Критерии готовности

1. Один клик ▶ проходит: классификация → анализ 3+ ниш параллельно → черновики
   формул в очереди Лаборатории → после утверждения пары формул следующий
   прогон приносит авто-approved брифы с бейджем «авто».
2. Падение одной ниши видно в отчёте звена и не валит прогон.
3. Кластеры «other» приезжают карточками предложений ниш.
4. Авто-пауза срабатывает на формуле с 3 reject из 5.
5. Ни одного git-конфликта от параллельных воркеров (git — только раннер).
