# Спека: дашборд Content Factory (CF)

Дата: 2026-07-14. Статус: согласована в брейншторме (назначение, экраны, конвейер, механика запуска, макеты — утверждены пользователем).

## Цель

Локальный веб-дашборд «контент-завода» JE LA PECHE: пульт оператора (одобрение брифов, запуск звеньев конвейера) плюс витрина метрик — в стилистике дизайн-системы бренда (`CF DS/DESIGN.md`). MVP предназначен для локальной работы владельца и демонстрации команде; хостинг и авторизация — вне охвата.

Макеты экранов «Обзор» и «Брифы» утверждены визуально в Pencil: `docs/design/cf-dashboard.pen` (примечание 2026-07-22: файл остался пустой заглушкой, макеты в него не рисовались; визуальным эталоном стал `CF DS/DESIGN.md` — сверка 2026-07-15, eedb47a).

## Ключевые решения

- **Данные — живые**, из тех же Google Sheets, что использует CF CLI (service-account уже настроен). Одобрение брифа в дашборде — реальное действие в системе.
- **Стек:** FastAPI + Jinja2 + htmx, один процесс. Стили — один CSS-файл на токенах DESIGN.md, без node-тулчейна.
- **Где живёт:** модуль `src/cf/dashboard/` в этом репозитории, поверх существующих `sheets.py` / `io.py` / `config.py` — ничего не дублируем.
- **Запуск:** `python -m cf dashboard` → `http://localhost:8787`, без авторизации.
- **Язык интерфейса** русский; допустимые технические термины: raw, ER, eval, имена команд `cf-*`.

## Архитектура

```
браузер ── htmx/HTML ── FastAPI (src/cf/dashboard/)
                          ├─ чтение/запись Sheets ── существующий код cf
                          ├─ запуск звеньев ── n8n API │ claude -p (subprocess)
                          ├─ health-чекер (фон, раз в минуту)
                          └─ кеш данных (60 с) + кнопка «Обновить»
```

- **Кеш:** все вкладки Sheets кешируются в памяти на ~60 секунд; принудительный рефреш кнопкой. Ошибка Sheets не роняет страницу: показывается кеш с жёлтой плашкой «данные устарели».
- **Пустые данные** — честный empty-state «недостаточно данных» (в духе правила insufficient_data).
- **Логирование:** каждое действие из дашборда (одобрение, запуск звена) пишется в CF Run Log тем же контрактом, что CLI.

## Навигация (тёмный сайдбар #131417)

Клеймо-монограмма + «JE LA PECHE / CONTENT FACTORY», шесть разделов, в подвале — индикатор систем и кнопка «Обновить». У пункта «Брифы» — голубой бейдж-счётчик очереди.

1. **Обзор** — главная.
2. **Брифы** — очередь ревью.
3. **Перформанс** — две вкладки: «Рилсы» (CF Published Reels) и «Метрики» (CF Performance).
4. **Запуски** — журнал CF Run Log: агент, команда, статус, время.
5. **Лаборатория** — вся техническая глубина: паттерны с evidence, формулы, версии промптов, очередь proposals, выводы eval. Read-only (промпты меняются только через git-ревью — железное правило CF).
6. **Источники** — raw-ленты TikTok/Instagram встроенной таблицей: референсы, метрики, ссылки.

## Экран «Обзор»

### Стат-плитки (4)

| Плитка | Содержание |
|---|---|
| Raw в базе · период | количество raw-роликов за выбранный период, разбивка TikTok/Instagram |
| Брифы ждут внимания | размер очереди на одобрение + возраст старейшего |
| Ждут статистики | опубликованные видео, по которым ещё не собраны метрики |
| Средний ER | по опубликованным за период, с дельтой к прошлому периоду |

Период выбирается селектором в шапке (по умолчанию 30 дней); все «машинные» цифры — Aeroport Mono.

### Конвейер (главный блок)

Пять звеньев слева направо, «пользовательская» логика без технических деталей:

| Звено | Актор | Живая цифра | Клик ведёт в |
|---|---|---|---|
| Raw-ролики | N8N | в базе за период | Источники |
| Контент-завод | CLAUDE CODE | в обработке | Лаборатория |
| Одобрение брифов | ПРОДЮСЕР | ждут решения | Брифы |
| Съёмка и публикация | ПРОДЮСЕР · N8N | рилсов вышло | Перформанс → Рилсы |
| Статистика | N8N | ждут данных | Перформанс → Метрики |

- Вся плитка кликабельна (переход в раздел); кнопка ▶ на плитке — отдельная зона клика, запускает только это звено. У ручного звена «Одобрение брифов» кнопки ▶ нет — вместо неё стрелка-переход в раздел «Брифы».
- Кнопка «Полный цикл» — прогон автоматических звеньев по очереди с живым прогрессом на схеме; на «Одобрении брифов» конвейер штатно останавливается и ждёт продюсера (human-in-the-loop не обходится). При ошибке или insufficient_data — останавливается и подсвечивает звено.
- Под плитками — **анимированная гусеница**: лента с роликами и шестерёнками по краям, движение слева направо чистым CSS; при `prefers-reduced-motion` анимация останавливается (направление остаётся понятным по стрелке).
- Внизу голубая строка-замыкание: «цикл замкнут: собранная статистика подпитывает следующий анализ».

### Остальное на «Обзоре»

График ER по неделям (столбики, лучшая неделя — фирменный голубой) и список последних запусков.

## Экран «Брифы»

- Фильтры-чипы: Все / Ожидают / Одобрены / Отклонены.
- Таблица-очередь: ID (mono), название, ниша (рамочный тег), статус (пыльные success/warning/error чипы), дата. Выбранная строка — голубая подложка.
- Карточка ревью справа: скрипт, референсы с evidence-метриками (просмотры, ER), формула-источник, поле «Заметка ревьюера», кнопки **«Одобрить»** (чёрная primary) и **«Отклонить»** (аутлайн на error).
- Одобрение/отклонение пишет `human_status` и `notes` в CF Creative Briefs + запись в CF Run Log — тот же контракт, что `cf set-review`.

## Механика запуска звеньев

- **n8n-звенья** (raw, публикация, статистика): вызов n8n API — `base_url` и ключ уже в `cf.config.json`.
- **Claude-звенья** (контент-завод): запуск Claude Code в headless-режиме (`claude -p "/cf-..."`) подпроцессом на машине пользователя; статус «выполняется…» на плитке, результат — в CF Run Log.
- Одновременно выполняется не более одного запуска на звено; повторный клик по работающему звену показывает статус, а не плодит процессы.

## Индикатор систем

Постоянная кнопка «Системы · LIVE» в подвале сайдбара с общей лампочкой (цвет — худший из статусов). По наведению раскрывается список с лампочками зелёная/жёлтая/красная:

- Google Sheets (доступность + время ответа),
- n8n (API отвечает, воркфлоу активны),
- Claude API (доступность),
- Данные (свежесть кеша / время последнего обновления).

Фоновый health-чекер обновляет статусы раз в минуту, не блокируя страницы.

## Чат с Клодом (этап 3)

Плавающая кнопка-пузырь внизу справа, чат выезжает шторкой поверх любого экрана. Бэкенд открывает сессию через Claude Agent SDK (Python) с рабочей папкой этого репозитория: Клод читает репо (формулы, промпты, память агентов) и вызывает читающие команды `cf` CLI — отвечает на «что по ситуации», «резюме недели», «почему упал ER». Ограничения MVP: только читающие инструменты (никаких записей в Sheets/git из чата), нужен API-ключ Anthropic. Реализуется после основных экранов, интерфейсная заглушка (кнопка) — сразу.

## Дизайн

- Всё по `CF DS/DESIGN.md`: палитра пантонов и производные, светлый канвас данных + тёмный сайдбар, пыльная семантика, радиусы/тени/моушен, фокус-кольцо.
- Шрифты: Aeroport (display, локальные файлы из `CF DS`), Montserrat (UI), Aeroport Mono (все цифры данных). В Pencil-макете Aeroport замещён фолбэком Montserrat — в вёрстке используется Aeroport.
- Внимание: Aeroport — trial-лицензия; для внутреннего инструмента приемлемо, перед любой публикацией нужна коммерческая лицензия.
- Макеты: `docs/design/cf-dashboard.pen` (экраны «Обзор», «Брифы»; примечание 2026-07-22: файл остался пустой заглушкой, макеты в него не рисовались — визуальным эталоном стал `CF DS/DESIGN.md`, сверка 2026-07-15, eedb47a). Остальные четыре экрана собираются из тех же паттернов (таблицы, чипы, теги, моно-цифры) без отдельных макетов.

## Тестирование

- pytest поверх существующего `tests/fakes.py` (фейковый Sheets-клиент): эндпоинты, действия с брифами, кеш, деградация при недоступном Sheets.
- Запуски звеньев тестируются с замоканными n8n API и subprocess.
- Health-чекер — с замоканными проверками.

## Вне охвата MVP

- Хостинг, авторизация, доступ команды извне.
- Запись в Sheets откуда-либо, кроме одобрения/отклонения брифов.
- Редактирование промптов/формул из интерфейса (только через git-ревью).
- Тёмная тема дашборда.
- Мобильная вёрстка (десктоп-first; не ломаться на планшете).

## Этапность

1. **MVP:** каркас + сайдбар + «Обзор» (плитки, конвейер с запуском, график, запуски) + «Брифы» с одобрением + индикатор систем.
2. Остальные разделы: Перформанс, Запуски, Лаборатория, Источники.
3. Чат с Клодом.
