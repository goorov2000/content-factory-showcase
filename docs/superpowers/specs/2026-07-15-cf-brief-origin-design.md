# Карточка брифа: секция «Почему этот бриф» (видимая цепочка происхождения)

Дата: 2026-07-15. Статус: дизайн согласован с оператором.

## Проблема

На карточке брифа оператор видит заголовок, скрипт и голые ссылки-референсы —
выглядит как случайный набор. Цепочка происхождения при этом **существует в
данных** (проверено на брифе `b-short-styling-idea-reel-20260715-summerbase`):

- бриф несёт `formula_id` и `source_pattern_ids` (колонки в CF Creative Briefs);
- оба референса карточки — evidence-ролики этих паттернов
  (`agent-runtime/patterns/*.json`, `evidence.source_urls`);
- формула (`formulas/_approved/index.json` → файл) несёт `problem_definition`
  («почему такой формат побеждает»), `solution_structure`, `confidence`,
  `source_pattern_ids`, `version`.

Ничего из этого UI не показывает. Чиним подачу — данные и агентов не трогаем.

## Решение (выбрано оператором: «Секция „Почему“ на карточке»)

На карточке выбранного брифа (`briefs.html`) блок «РЕФЕРЕНСЫ» заменяется
секцией **«ПОЧЕМУ ЭТОТ БРИФ»** между скриптом и заметкой ревьюера:

1. **Формула**: `short-styling-idea-reel · v2 · мужские-образы · утверждена
   2026-07-14 · confidence medium`, ниже — `problem_definition` одним абзацем
   приглушённым кеглем (обрезка ~300 символов по границе слова, с «…»).
2. **Паттерны** (по `source_pattern_ids` брифа), для каждого:
   - бейдж платформы (TikTok/Instagram — из `meta.source_tab` файла паттернов);
   - формулировка `description`;
   - метрики: `N роликов · avg views · avg ER` (числа в mono);
   - список evidence-URL (кликабельные); URL, совпавшие с референсами брифа,
     помечены «→ референс этого брифа».
3. **Честные fallback'и:**
   - референс брифа, не найденный ни в одном evidence перечисленных паттернов →
     отдельный подблок «Референсы вне evidence» с жёлтым бейджем (это сигнал
     ревьюеру — так выглядел бы инцидент 2026-07-14 с мусорными брифами);
   - `pattern_id` без файла → строка с id и пометкой «файл паттерна не найден»;
   - у брифа нет ни `formula_id`, ни `source_pattern_ids` (старые брифы) →
     строка «агент не записал происхождение» вместо секции;
   - `formula_id` есть, файла формулы нет → имя формулы с пометкой «файл не
     найден».

## Механика

Новая чистая функция `sections.py::brief_origin(selected, references, root=".")`
(рядом с `lab_context`, использует существующий `_load_json`):

- **Формула**: `formulas/_approved/index.json` → запись `name == formula_id` →
  файл по `path`. Поля: name, version, niche, approved_at (10 симв.),
  confidence, problem (обрезанный `problem_definition`).
- **Паттерны**: `agent-runtime/patterns/*.json`, файлы в обратном порядке имён
  (даты в имени — свежайший файл с данным `pattern_id` побеждает). Поля:
  pattern_id, description, confidence, платформа из `meta.source_tab`
  (`raw_tiktok` → «TikTok», `raw_instagram` → «Instagram», иначе — как есть),
  avg_views, avg_er, evidence: `[{url, is_reference}]`.
- **Матчинг URL**: нормализация — `strip()` + `rstrip("/")`; совпадение
  референса брифа с evidence-URL даёт `is_reference: True`; референсы без
  совпадений → `unmatched_refs`.
- `source_pattern_ids` в строке Sheets — строка вида `"id1, id2"` → парсить по
  запятой (в `payload_json` есть список, но парсить строковую колонку проще и
  устойчивее).
- Возврат: `{"formula": {...}|None, "patterns": [...], "unmatched_refs": [...],
  "missing_pattern_ids": [...]}` либо `None`, когда нет ни formula_id, ни
  pattern ids. Ошибки чтения файлов не роняют страницу (`_load_json` → None).

Подключение: `app.py::_briefs_context` дополняет контекст ключом
`origin = brief_origin(selected, references, root=lab_root)`; `lab_root` уже
инъецируется в `create_app`. Шаблон `briefs.html`: секция вместо блока
«РЕФЕРЕНСЫ». Новый CSS не нужен (используются `field-label`, `tag`, `badge`,
`mono`, `caption`-кегли); допустим один мелкий класс для отступов, если без
него никак.

## Тесты

- `brief_origin`: полная цепочка (формула + 2 паттерна + матчинг рефов);
  реф вне evidence → `unmatched_refs`; pattern_id без файла →
  `missing_pattern_ids`; бриф без происхождения → None; нормализация URL
  (трейлинг-слэш); свежайший файл побеждает при дублях pattern_id; битый JSON
  не роняет.
- Роут `/briefs?id=...`: секция рендерится (маркеры «ПОЧЕМУ ЭТОТ БРИФ»,
  описание паттерна, пометка референса); бриф без происхождения → «агент не
  записал происхождение».

## Вне охвата

- Отдельная страница-трасса до сырых строк raw-таблиц.
- Изменения агентов, промптов, схемы Sheets, дозапись старых брифов.
- Пер-элементная разметка скрипта («0-3с ← из формулы») — возможное развитие.
