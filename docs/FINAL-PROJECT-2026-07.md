## 1. Какой проект выбран

**Content Factory** — контент-завод для собственного бренда мужской одежды
JE LA PECHE. Задача бизнеса: перейти с маркетплейсов на продажи со своего сайта,
для этого нужен свой трафик из коротких видео (TikTok/Instagram).

Рутина, которую он забирает: каждый день найти чужие залетевшие ролики в нужных
нишах, посчитать, какие приёмы реально работают (а не «кажется, что работают»),
вывести из них рецепты и написать по рецептам готовые сценарии для съёмки.
Раньше это был ручной труд продюсера, теперь — конвейер, где человек принимает
одно решение: что снимать.

Целевая мощность бизнеса — 70 роликов в неделю на 5 аккаунтах. Это цель, а не
текущий результат; см. раздел 5.

## 2. Формат: связка агентной системы и SaaS-контура

Это **связка**, и обе половины настоящие:

- **Агентная система.** 12 агентов на Claude Code с промптами в git
  (`prompts/agents/*.md`) и 14 слэш-командами: классификатор ниш, профайлер
  батча, аналитик паттернов, автор рецептов, судья рецептов, генератор
  сценариев, ревьюер сценариев, правщик забракованных, eval-агент, оптимизатор
  промптов, тюнер источников, автор промптов тем.
- **SaaS-контур.** Веб-пульт на FastAPI на своём VPS: публичный домен под HTTPS
  с паролем (Caddy), systemd-таймеры гоняют цикл без человека, Telegram-бот
  шлёт сводки, Google Sheets — операционное хранилище, git — версионируемое.

Ключевой архитектурный принцип: **агент оценивает смысл → код применяет правила
→ человек принимает бизнес-решение.** Агенту никогда не отдаётся то, что можно
проверить детерминированно, и наоборот.

## 3. Принцип работы

Один замкнутый цикл из 15 этапов:

```
сбор роликов → разметка тем → анализ приёмов → черновики рецептов
   → [ворота: одобрение рецептов]  ← закрывает машина
   → черновик промпта темы → [ворота: включение промпта темы]  ← закрывает машина
   → сценарии → ревью → доработка → [ворота: одобрение сценариев]  ← закрывает человек
   → съёмка и публикация → статистика → eval → правка промптов → назад в цикл
```

Три вещи, которые отличают это от «обёртки над LLM»:

**Трассировка.** Для любого сценария можно ответить, из каких чужих роликов он
родился и как отработал:
`source_url → pattern_id → formula_id → brief_id → prompt_version → reel_id → performance`
(команда `cf trace <brief_id>`).

**Честное «данных мало».** Если выборка не даёт вывода, система пишет
`insufficient_data` и перечисляет, чего не хватает, вместо того чтобы выдумать
паттерн. В журнале 567 прогонов таких **69** — то есть механизм не декоративный,
он срабатывает в каждом восьмом прогоне.

**Ворота вместо кнопок на всё.** Изначально человек кликал на каждое решение.
Калибровка машинного чек-листа на его же прошлых решениях показала, что клик
подменяет собой недостающую проверку, а не добавляет суждение — и двое ворот из
трёх стали машинными (`cf gate-calibration`: 18 совпадений из 22, 1 раз машина
строже человека, 3 пропуска — их закрывает агент-судья). За человеком остались
только сценарии: дальше идёт съёмка, то есть его время и деньги. Возврат в
ручной режим стоит одной строки в конфиге.

Цена ошибки авто-решения ограничена конструкцией: плохой рецепт даёт ограниченное
число сценариев, их бракует ревьюер, а сторож снимает рецепт с производства после
3 отказов из 5 — ещё до того, как появится хоть одна метрика.

## 5. Что честно НЕ сделано

**Реальных публикаций пока ноль.** Все 46 строк в CF Published Reels помечены
`demo` — это фиктивные данные, которые стираются одной командой. Бренд сейчас в
переходной фазе: продюсер ещё не нанят, владелец снимает сам, поэтому нижнее
звено конвейера (съёмка → публикация) физически не запущено.

Верхние 12 звеньев из 15 работают на боевых данных. Нижние три — съёмка,
статистика, обучение на своей статистике — проверены иначе, и это отдельный
результат:

**Слепая проверка петли обратной связи.** Чтобы не ждать реальных публикаций
месяцами, сгенерированы 35 фиктивных роликов с метриками, спроектированными от
нужного вывода. Ключ ответов — что именно система обязана заметить — был написан
**до** прогона и запечатан. Система прошла его **12 из 12**, включая два
отрицательных контроля (случаи, где правильный ответ — промолчать, потому что
выборка мала). Заодно нашлись три реальных дефекта, которые иначе всплыли бы уже
на боевых данных.

То есть на защите я показываю не обещание, что петля заработает, а измерение, что
она работает — с известной заранее меркой.

**Следующий шаг:** первые реальные публикации и найм продюсера. Тогда те же
механизмы поедут на настоящих метриках, а не на симуляции.

## 6. Что показывать в VS Code (сценарий демо на 3–4 минуты)

1. **Живая система, а не проект в папке** — `systemctl list-timers | grep cf`:
   таймеры отработали сегодня, следующий запуск завтра в 07:30.
2. **Пульт** — дашборд на `cf.example.com`: лента конвейера, ворота с
   подписью, кто их закрывает, очередь съёмки с назначением исполнителя.
3. **Трассировка** — `cf trace <brief_id>`: от готового сценария вниз до чужих
   роликов, из которых он выведен, с их метриками.
4. **Честность как код** — `cf gate-calibration`: система сама сверяет свои
   решения с прошлыми решениями человека и печатает, где разошлась.
5. **Тесты** — `pytest -q`: 1 688 зелёных за полторы минуты.
6. **Промпты в git** — `prompts/agents/`: агент не может править их напрямую,
   только через аппликатор с чек-листом. Правка действующего промпта идёт
   кандидатом в A/B рядом с рабочей версией; промпт не утверждается — он
   выигрывает сравнение.

## 7. Технический контур

```
TikTok + Instagram → Apify API → Google Sheets (операционные данные)
                                        ↓
                        Ubuntu VPS: cf CLI · StageRunner · Claude CLI
                        FastAPI-дашборд · systemd · Caddy (HTTPS + пароль)
                                        ↓
                        git / GitHub: промпты, рецепты, решения, источники
```

Стек: Python 3.12, FastAPI, gspread, pytest, Apify, Claude Code (по подписке, не
по API-ключу), systemd, Caddy, Telegram Bot API.

Отдельно стоит сказать, что n8n, с которого проект начинался, был **выведен из
эксплуатации 24.07**: сбор портирован на Python в репозиторий. Причина — в n8n
логика жила в UI, её нельзя было ни проверить тестами, ни откатить коммитом.
Каталог `n8n/` оставлен замороженным архивом, потому что он — доказательная база
для прошлых выводов, а не мусор.
