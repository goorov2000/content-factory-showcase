# UX-исследование дашборда CF (2026-07-25)

**Задача:** большое исследование удобства всех разделов дашборда.
**Аудитория:** новый SMM-продюсер на онбординге (по [BUSINESS-CONTEXT.md](BUSINESS-CONTEXT.md) — второй пользователь дашборда; получает готовые сценарии и аналитику, раздаёт криэйторам; не разработчик, не знает внутренний жаргон).
**Фокус:** ясность → навигация → визуальная доводка.
**Метод:** воркфлоу-аудит, 10 агентов (7 разделов + 3 сквозных среза), каждый — по коду шаблонов, живому HTML с :8787 и трём линзам: Vercel Web Interface Guidelines, принципы frontend-design, «глазами новичка». Скиллы: `web-design-guidelines` (Vercel), `frontend-design` (Anthropic).
**Полный перечень:** [ux-research-2026-07-25-findings.md](ux-research-2026-07-25-findings.md) — все 141 находка с location и правкой.
**Визуальный аудит (живой рендер, 4 ширины):** [ux-research-2026-07-25-visual.md](ux-research-2026-07-25-visual.md) — адаптивность и ломка вёрстки, чего не видно в коде.

## Вердикт в одну строку

Дашборд функционально силён и визуально аккуратен, но **говорит языком системы, а не продюсера**. Новичок не понимает, что перед ним, где его зона ответственности и что означают числа — потому что интерфейс подписан внутренними терминами (`ниша`, `формула`, `паттерн`, `бриф`, `eval`, `RAW`, `ER`, `фан-аут`), именами инструментов (`N8N`, `CLAUDE CODE`), слагами агентов и названиями Google-таблиц.

**Находок: 141** (51 high, 77 medium, 13 low). Распределение по типам: ясность 59, консистентность 27, контент 18, доступность 13, визуал 13, навигация 11. Ясность доминирует в каждом без исключения разделе — это не косметика, а корневая проблема.

## Приоритет 1 — Языковой слой (корень 60% находок)

Одно решение закрывает большинство проблем: **завести единый словарь «система → пользователь» и прогнать его по всем шаблонам**. Это в основном правки текста (copy), а не переписывание логики — максимальный эффект при минимуме риска. Термин упоминается в находках: `бриф` 96 раз, `формула` 78, `RAW` 37, `паттерн`/`eval` по 33, `ниша` 31, `промпт` 29.

Рекомендованный словарь (сведён из находок; финальные слова — за тобой):

| Сейчас (язык системы) | Предлагается (язык продюсера) |
|---|---|
| бриф / скрипт / рил / reels | **сценарий** (ролика); опубликованное — **ролик** |
| ниша | **тема** (контента) |
| формула | **рецепт ролика** / проверенный приём |
| паттерн | **рабочий приём** |
| RAW / raw-видео / Raw-ролики | **собранные ролики** (конкурентов) |
| ER | **вовлечённость** (с расшифровкой при первом показе) |
| eval | **оценка результатов** (за неделю) |
| фан-аут / approved-индекс / prompt version | убрать из вида продюсера |
| N8N | **автосбор**; CLAUDE CODE → **ИИ-аналитик/система**; ПРОДЮСЕР → **вы** |
| approved / reject / revise / recommend / insufficient_data | утверждено / отклонить / доработать / рекомендовать / данных мало |

Критично внутри этого слоя (все high):
- **Одна сущность — одно слово.** Опубликованный ролик зовётся четырьмя способами, включая английское `{{ reels }} reels` ([lab.html:188](../src/cf/dashboard/templates/lab.html#L188)). Сценарий — тремя (`бриф`/`скрипт`/`рил`). Это подрывает доверие: новичок думает, что цифры про разное.
- **`ER` расшифровать и форматировать одинаково.** Сейчас три формата: `25.6%`, сырая доля `0.078` ([performance.html:47](../src/cf/dashboard/templates/performance.html#L47)), `er 0.21843` ([lab.html:212](../src/cf/dashboard/templates/lab.html#L212)). Везде процент + подпись «Вовлечённость».
- **Имена инструментов → роли** на плитках конвейера ([stages.html:5-9](../src/cf/dashboard/templates/partials/stages.html#L5)): «N8N/CLAUDE CODE/ПРОДЮСЕР · N8N» ничего не говорят новичку о том, где действует он, а где «оно само».

## Приоритет 2 — Навигация и информационная архитектура

Новичок не может с первого взгляда отделить «разделы про мою работу» от «внутренней кухни».

- **Навбар — на жаргоне и транслите** ([base.html:21](../src/cf/dashboard/templates/base.html#L21)): «Лаборатория», «Перформанс», «Источники». Продюсер не догадается, что обещанные ему «сценарии и аналитика» живут за «Лабораторией». Переименовать в задачи: Обзор→Главная, Брифы→Сценарии, Перформанс→Результаты, Источники→Референсы конкурентов, Лаборатория→Аналитика.
- **Главный ежедневный инструмент продюсера — «Очередь съёмки» — не имеет пункта меню** ([briefs.html:14](../src/cf/dashboard/templates/briefs.html#L14)): спрятан чипом-фильтром внутри /briefs. Вынести в навбар.
- **Разделы называются по-разному в меню и на карте «Конвейер»**: /sources = «Источники» в меню и «Raw-ролики» на плитке; /lab = «Лаборатория» и «Контент-завод». Свести к одному словарю.
- **Надстрочник (eyebrow) каждого раздела — имя внутренней Google-таблицы**, а не описание: «CF CREATIVE BRIEFS», «CF PUBLISHED REELS · CF PERFORMANCE», «CF RAW». Заменить на строку-назначение раздела человеческим языком.
- **Нет «первого шага»** при первом входе — новичок не знает, с чего начать.

## Приоритет 3 — «Обзор» перестаёт быть обзором

Главный экран сейчас — самый шумный (4 high).

- **Строка-воронка на жаргоне + английский посреди русского** ([overview.html:60-63](../src/cf/dashboard/templates/overview.html#L60)): «ниш с промптом 1 из 4 · формул approved 7 · брифов за неделю 2». Переписать человеческой сквозной шкалой.
- **Сырой лог агентов на главной** ([overview.html:82-107](../src/cf/dashboard/templates/overview.html#L82) + [reports.html](../src/cf/dashboard/templates/partials/reports.html)): `batches=7 rows=519 kept=257…`, пути `agent-runtime/…`, `NICHE_RESULT: {…}` и **английские ошибки** «You've hit your session limit» / «You've reached your Fable 5 limit». Новичок пугается — думает, что что-то сломал. Показывать только то, что требует человека; тех-дампы свернуть/увести в «Запуски»; ошибки Claude переводить в «Система была занята, повторит позже».
- **Первая метрика подписана «RAW В БАЗЕ»** ([overview.html:33](../src/cf/dashboard/templates/overview.html#L33)) — плохой первый контакт.
- **Три разных числа про «брифы» на одном экране** без пояснения охвата (ждут решения 0 / за период 10 / темп 2 из 70).

## Приоритет 4 — Ясность по разделам (топ каждого)

- **Брифы** ([briefs_review.html](../src/cf/dashboard/templates/partials/briefs_review.html)): заголовок карточки — три системных ID вместо самого хука; блок «Почему этот бриф» показывает кухню ревьюера (`formula_id`, `evidence`, «вне evidence», «файл паттерна не найден») вместо «что снимать и почему сработает». Сделать заголовком карточки сам хук, слаги — под кат, предупреждения перевести на язык и роль продюсера.
- **Список на съёмку** ([shooting-list.html](../src/cf/dashboard/templates/shooting-list.html)): нет ни строки «что это и что делать»; верхняя подпись карточки — стена слагов; классы `.shooting-list/.shooting-group` **вообще не описаны в CSS** (вёрстка на инлайнах). Добавить лид, спрятать ID, завести классы.
- **Лаборатория** ([lab.html](../src/cf/dashboard/templates/lab.html)): просит необратимые решения (Утвердить/Отклонить формулу) языком, которого новичок не знает; card-sub — файловые пути (`formulas/*/*.json · status=proposed`); на исключённой нише два красных пилла + сырой путь конфига. Добавить вводные, перевести подписи, для исключённой темы гасить «Утвердить».
- **Запуски** ([runs.html](../src/cf/dashboard/templates/runs.html)): само слово читается как «запуск кампании», а это тех-лог; столбцы — слаги агентов и debug-дампы; «Успех» стоит даже там, где внутри красная ошибка; пагинация отрендерена классом пустого состояния и тащит большой водяной знак-логотип. Переименовать, завести словарь агентов, человеческая сводка события, отдельный класс подписи таблицы.
- **Performance** ([performance.html](../src/cf/dashboard/templates/performance.html)): живьём — тупик «Недостаточно данных» без подсказки; когда данные будут — колонки на языке БД (`ER` сырой долей, «Промпт» = version-id, машинные ID вместо названий). Пустое состояние сделать приглашением со ссылкой на /briefs.
- **Источники** ([sources.html](../src/cf/dashboard/templates/sources.html)): голая таблица 200 строк без объяснения; колонка «Хук» — 200 прочерков; заголовки «Views/Likes/Comm/Saves» вперемешку с русским; семизначные числа без разделителей; нет сортировки/фильтра, чтобы найти удачные референсы (главная задача продюсера); в живых данных — дубли и мусорные аккаунты.

## Приоритет 5 — Долг дизайн-системы и порог доступности

- **Дизайн-система живёт наполовину**: хорошие токены, но повторяющиеся паттерны — десятками инлайн-стилей (~52 из ~61 инлайна в briefs_review.html и lab.html). Одно и то же (карточка-таблица, строка-URL, приглушённый текст) свёрстано по-разному → «страницы собирали разные люди».
- **Montserrat объявлен, но не загружен** — интерфейс на большинстве машин рисуется системным шрифтом, вес 600 синтезируется.
- **`.empty-state` обслуживает три смысла** (пустота / ошибка / подпись таблицы) и во всех рисует водяной знак-логотип 96×96 ([style.css:144](../src/cf/dashboard/static/style.css#L144)) — логотип всплывает под ошибками и пагинацией. Разделить на `.empty-state` / `.banner.error` / `.table-foot`.
- **Карточка-таблица с `overflow:hidden`** (инлайн в 4 шаблонах) обрезает широкие 9-колоночные таблицы — заменить на `.card--table { overflow-x:auto }`.
- **Порог доступности**: селекторы периода без label/aria-label; заголовки карточек — `div`, не `h*`; нет skip-link; иконка-ссылка «↗» без aria-label и с пустым `<th>`. Всё чинится дёшево.
- **DESIGN.md отсутствует**: README ссылается на спецификацию дизайн-системы (`DESIGN.md`), но файла по путям нет — либо потерян, либо не создан. Документация ДС отсутствует.

## Рекомендованная последовательность

Отсортировано по «эффект / усилие» — сверху самое выгодное:

1. **Языковой слой + eyebrows + навбар (Приоритеты 1–2).** Почти целиком правки copy → снимают большинство high-находок про ясность и навигацию. Начать с единого словаря и одной сущности-одного-слова. **Самый большой выигрыш, минимальный риск.**
2. **Чистка «Обзора» (Приоритет 3).** Убрать сырой лог и англ-ошибки с главной, переписать воронку. Средне по усилию, высоко по эффекту (первый экран).
3. **Ясность по разделам (Приоритет 4).** Заголовки-хуки в брифах/съёмке, вводные строки, человеческие пустые состояния, словарь агентов в «Запусках».
4. **Долг дизайн-системы (Приоритет 5).** Вынести инлайны в классы, загрузить шрифт, разделить `.empty-state`, починить overflow таблиц. Разово оздоровляет всё.
5. **Порог доступности + сортировка «Источников».** Дешёвые a11y-правки; сортировка/фильтр референсов — отдельная фича.
6. **Восстановить/написать DESIGN.md** — чтобы дизайн-система снова имела источник истины.

**Быстрые победы на один заход** (copy-only, почти без риска): eyebrows всех разделов, переименование навбара, «одна сущность — одно слово» для сценария/ролика, единый формат ER, перевод actor-плиток и англ-ошибок. Это уже сдвинет ощущение «сервис для разработчика» → «сервис для меня».

## Оговорки

- Исследование велось под **одну** аудиторию (новый продюсер). Часть находок (напр. слаги агентов в «Запусках») для тебя-владельца — не баг, а нужная диагностика; правки должны прятать тех-детали от продюсера, но **сохранять** их доступными (под кат / в «Запусках»), а не удалять.
- Находки проверены по коду и живому HTML на 2026-07-25; номера строк могут сдвинуться после правок — сверяйся по цитате текста.
