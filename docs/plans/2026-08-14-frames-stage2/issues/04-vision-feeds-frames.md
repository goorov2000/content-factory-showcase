## Что построить

При `frames_enabled=true` движку подаются обложка и кадры строки: кадры
сверх капа проходят через выборщик (тикет 02), обложка подаётся отдельно и в
кап не входит. Кап — ключ конфига `vision.frames_cap` (целое ≥ 2), дефолта в
коде НЕТ: дефолт выставит вердикт пилота. Включение `frames_enabled=true`
без капа в конфиге — громкий инфраструктурный отказ прогона (семантика v1:
остановка, не `failed` строк). Пилотные прогоны задают кап флагом
`--frames-cap` поверх конфига.

Блок медиа в запросе движка дополняется строкой метаданных подачи: сколько
кадров подано из скольких, длительность ролика (если известна из манифеста
тикета 01), правило нумерации («номер ≈ секунда» посекундного режима либо
«равномерно по N секундам» растяжки). Пути кадров несут исходные номера —
`frame:N` в ответе указывает на реальный файл.

Сентинел этапа 1 «кадры есть, обложки нет» отдельной обработки не требует:
у таких строк `visual_status` пуст, при включённых кадрах они входят в
обычную очередь — сентинел исчерпывает себя конструкцией. `batch_limit`
не меняется. Прочая семантика v1 (идемпотентность разбора, Run Log,
валидация схемой) не меняется.

## Критерии приёмки

- [ ] С fake-движком при включённых кадрах в запрос уходят обложка +
      субвыборка кадров + строка метаданных подачи; исходные номера кадров
      в путях сохранены.
- [ ] `frames_enabled=true` без `vision.frames_cap` — громкий останов
      прогона до платных вызовов; строки в `failed` не уходят.
- [ ] `--frames-cap` переопределяет конфиг; значение < 2 — отказ.
- [ ] Строки-сентинелы («кадры есть, обложки нет») уходят в разбор при
      включении кадров без спецкода.
- [ ] Ответ движка валидируется схемой с полями кадрового режима (тикет 03);
      старые манифесты без длительности дают честную строку метаданных без
      неё.
- [ ] Поведение при `frames_enabled=false` байт-в-байт прежнее (v1-режим
      не регрессирует).
