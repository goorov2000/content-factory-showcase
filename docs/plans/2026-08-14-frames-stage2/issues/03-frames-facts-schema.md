## Что построить

Схема визуальных фактов (kind `visual-facts` в `cf validate`) получает три
новых ОПЦИОНАЛЬНЫХ поля, легальных только при `observed_media: "frames"` —
зеркально существующему запрету frame-ссылок по одной обложке:

- `narrative_structure` — строка: развитие ролика по поданным кадрам
  (структура, смены сцен, где стоит хук);
- `cta_visual` — строка: что видно в финальных кадрах (развязка, CTA);
- `frames_analyzed` — целое: сколько кадров движок реально прочитал
  (материал аудита честности и пилота).

При `cover`/`none` схема эти поля запрещает. «Текст на экране по кадрам»
отдельным полем не заводится: `screen_text` остаётся общим списком,
покадровая привязка — записями `visual_evidence` с `media_ref: "frame:N"`.
Существующие ограничения не меняются: при `cover` — только cover-ссылки, при
`none` — пустой evidence; `observed_media: "frames"` означает «видел кадры»
(обложка могла подаваться тоже, cover-ссылки легальны). Ворота
`visual_refs_resolve` не трогаются: `frame_index` в пределах числа кадров
манифеста, субвыборка на это не влияет.

## Критерии приёмки

- [ ] Валидная фикстура кадрового режима (все три поля + смесь cover- и
      frame-ссылок) проходит `cf validate`.
- [ ] Фикстуры-нарушители падают: любое из трёх полей при
      `observed_media: "cover"` и при `"none"`; `frames_analyzed` не-целое.
- [ ] Факты без новых полей (выход v1) остаются валидными — расширение,
      не ломка.
- [ ] Существующие тесты validate и ворот `visual_refs_resolve` не
      регрессируют.
