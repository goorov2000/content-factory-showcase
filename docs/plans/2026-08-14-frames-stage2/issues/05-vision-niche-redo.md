## Что построить

Два новых флага `cf vision`:

- `--niche` (сочетается с существующим `--tab`): очередь ограничивается
  строками ниши. В нишевом режиме лимит по умолчанию — ВСЯ очередь ниши
  (решение №8 гриля: платим ровно за то, что будет прочитано); явный
  `--limit` уважается. Этот флаг — опора шага vision в воркере цикла
  (тикет 07).
- `--redo` — ре-разбор строк с уже выставленным `visual_status` (`done` и
  `failed`): требует явной адресации — перечисление строк (`--raw-id`,
  повторяемый) либо ниша (`--niche`, с `--tab` или без); без адресации —
  отказ, «ре-разбор всего» невозможен. Факты перезаписываются обычным
  апсертом. Авто-догона `done`-строк нет нигде (решение №9 гриля).

Прочая семантика v1 не меняется: без `--redo` разобранное не
пере-разбирается, инфраструктурный отказ останавливает прогон громко,
каждый прогон — в Run Log (правило №6).

## Критерии приёмки

- [ ] `--niche` ограничивает очередь строками ниши и снимает лимит по
      умолчанию; явный `--limit` уважается; сочетание с `--tab` сужает до
      вкладки.
- [ ] `--redo` без `--raw-id`/`--niche` — отказ с внятной причиной.
- [ ] `--redo --raw-id` пере-разбирает указанные строки (`done` и `failed`),
      факты перезаписываются; `--redo --niche` — все размеченные строки ниши.
- [ ] Без `--redo` поведение прежнее: `done`-строки в очередь не попадают.
- [ ] Каждый прогон логируется в Run Log с числами разбора.
