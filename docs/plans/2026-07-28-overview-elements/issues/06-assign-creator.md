# 06 — «Отдал в работу» на «Очереди съёмки»

**Blocked by:** нет — можно брать сразу
**Status:** ready-for-agent
**Type:** enhancement

ТЗ: [решения владельца](../../../design/2026-07-28-overview-elements.md),
раздел С4 и хвосты опроса («Список слотов-исполнителей», «Жизнь сценария после
назначения»). Этап 2 порядка работ — весь этап целиком.

Расширение границ за `/overview` санкционировано владельцем в ходе опроса: без
этой механики две новые плитки и среднее полукольцо измеряют несуществующий
процесс.

## Что построить

Продюсер открывает «Очередь съёмки», у каждого одобренного сценария видит кнопку
«Отдал в работу», выбирает слот исполнителя — и сценарий получает метку вида
«криэйтор-1, с 28.07».

* **Слоты — значения поля**, а не люди: `криэйтор-1`, `криэйтор-2`. Список живёт
  новым ключом в `cf.config.json`; при найме слот переименовывается одной правкой
  в одном месте.
* **Запись** — колонка-слот и дата назначения в `CF Creative Briefs`. Колонки
  исполнителя там сегодня нет; `creator`/`content_owner` живут в опубликованных
  роликах и заполняются, когда ролик уже вышел, — для очереди это поздно.
* **Сценарий остаётся в очереди** с меткой: назначение можно сменить и снять.
* Из плитки «Ждут назначения» назначенный уходит, в среднее кольцо входит —
  плитки и кольца строит этап 3.

Отсутствие колонки в листе должно давать **видимую ошибку**, а не тихий no-op:
назначение — суть тикета, молча потерять его нельзя. Это не то же, что
необязательные поля вроде даты ревью, где no-op допустим.

## Критерии приёмки

- [ ] новый ключ конфига задаёт список слотов; пустой или отсутствующий ключ не
      роняет экран, а прячет кнопку с внятной причиной
- [ ] назначение пишет слот и дату в лист сценариев; в очереди появляется метка
      «слот, с ДД.ММ»
- [ ] назначение можно сменить на другой слот и снять совсем
- [ ] если колонок в листе нет — назначение не сохраняется и продюсер видит
      ошибку; тест на этот путь есть
- [ ] выгрузка списка в .md по-прежнему работает и несёт метку исполнителя
- [ ] решение назначения оставляет след в CF Run Log, как это делает решение по
      сценарию
- [ ] тесты зелёные; `/briefs`, `/lab`, `/performance`, `/sources` не тронуты
