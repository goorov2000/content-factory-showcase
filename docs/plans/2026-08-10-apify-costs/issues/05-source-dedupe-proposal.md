# 05 — Дубли источников вычищены законным путём

**What to build:** Один тег не должен собираться и оплачиваться дважды. По
хэндоффу §5 в реестрах есть дубли (один и тот же тег как hashtag и как search:
два тега в Instagram, один в TikTok) — точный список НУЖНО УСТАНОВИТЬ по текущим
реестрам (после применённых proposals 02.08/09.08 состав мог измениться).
Дубли снимаются так, как положено реестру: proposal с обоснованием →
валидация → применение аппликатором (`cf apply-sources`). Руками реестр не
правится. Из пары дублей выживает запись с историей (статистика
прогонов/harvest), уходит пустышка.

**Blocked by:** None — can start immediately.

**Протокол поиска** (программно по обоим реестрам; нормализация query: NFC,
lowercase, trim, без ведущего `#`):

- Дублей одного query **одного kind** — ноль в обоих реестрах (буквальное
  чтение критерия выполнялось ещё до правки).
- Дубли одного query **двумя kind** (ровно те, что назвал хэндофф §5, состав
  после proposals 02.08/09.08 не изменился — оба лежат pending и не применены):
  - TikTok: один тег — hashtag + search, оба active c 23.07;
  - Instagram: два тега — hashtag + search, все active c 23.07.
- НЕ дубли (разные строки query = разные теги/запросы, не тронуты): пары
  «слитное написание / с пробелом» одного словосочетания.

**Кто выжил и почему** (evidence — отчёты
`agent-runtime/source-stats/2026-08-09-raw_{tiktok,instagram}-source-stats.json`,
вся история вкладок на 09.08). Таблица с реальными источниками и их метриками
(строки, целевые строки, yield) в витринной копии не публикуется; ниже — методика:

- TikTok: обе записи пары оказались живыми — не «история против пустышки»,
  решала большая собранная история: выжила search-запись (больше строк и
  целевых строк), ретайрена hashtag-запись; search-контур из 5 источников
  (user story 6 спеки) сохранён целиком.
- Instagram: выжили hashtag-записи, ретайрены search-записи — по 0 строк за
  всю вкладку. Это пустышки конструктивно:
  search-записи IG строк не собирают вообще (discovery хэштегов
  search-скрейпером, строки приносят только hashtag-батчи), а запрос, дословно
  равный активному сид-хэштегу, тратит платный discovery-вызов на
  переоткрытие собственного тега.
