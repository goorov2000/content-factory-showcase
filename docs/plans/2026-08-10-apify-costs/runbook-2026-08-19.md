## §2. Смоук сборщиков (в порядке задания; цены — потолок при полном филле)

Про `--dry-run` (см. `cmd_collect`, src/cf/cli.py): реальный Apify, БЕЗ записи
в Sheets; строки уезжают в `agent-runtime/collect/dry-run-<stage>-<штамп>.jsonl`,
след пишется в CF Run Log (trigger `dry-run`). Лимит dry-run — **1 батч**
(`--batches N` переопределяет, `0` = все батчи). Батчи TikTok режутся по kind,
**hashtag-батчи идут первыми** (make_batches, src/cf/collect/sources.py):
на реестре от 10.08 (13 hashtag + 5 search) это батчи 0–3 hashtag и 4–5 search.
Если реестр к 19.08 изменился — пересчитать индексы по этому правилу.

### 2.1 TikTok, hashtag-ветка (≈$0.16)

```bash
.venv/bin/python -m cf collect tiktok --dry-run
```

Один dry-run покрывает **только первый hashtag-батч** (первые 4 активных
хэштега реестра: мужскаяодежда, мужскиеобразы, мужскойстиль, мужскойгардероб)

- **Ожидаемо:** stdout `dry-run: N строк -> agent-runtime/collect/dry-run-tiktok-….jsonl`
  (N ≈ 40–80: запрошено 80, гейт режет), затем `collect tiktok: success` и
  сводка `batches=1 rows=… kept=… subtitles ok=K failed=F upsert updated=0 appended=0`.

Что актор верный (в JSONL это не видно: `source_actor` у обеих
clockworks-веток — легаси-константа `clockworks/tiktok-scraper`):

```bash

  "https://api.apify.com/v2/acts/clockworks~tiktok-hashtag-scraper/runs/last" \
  | .venv/bin/python -c "import json,sys; d=json.load(sys.stdin)['data']; print(d['status'], d['startedAt'])"
```

Ожидаемо: свежий (минуты назад) `SUCCEEDED` ран hashtag-scraper.

Поля строк:

```bash
.venv/bin/python - <<'EOF'
import json, glob
from collections import Counter
path = sorted(glob.glob("agent-runtime/collect/dry-run-tiktok-*.jsonl"))[-1]
rows = [json.loads(l) for l in open(path, encoding="utf-8")]

print("processing_status:", Counter(r.get("processing_status") for r in rows))
print("source_query:", Counter(r.get("source_query") for r in rows))

EOF
```

Ожидаемо: колонок не хватает — пусто; `source_query` только `hashtag:#…`;
`processing_status` из {`raw_saved_actor_transcript`,
`raw_saved_no_actor_transcript`, `raw_saved_subtitle_download_failed`}
(`subtitle_pending_download` остаться не должен — субтитры скачиваются в том
же прогоне, бесплатно); заметная часть строк с транскриптом (историческая
норма clockworks — примерно половина и больше).

- **Провал:** `collect tiktok: failed` (403 → лимит: назад в §1.1; 401 →
  токен), `insufficient_data` с `деградация: …` (батч потерян — причина в
  сводке), 0 строк, или нет свежего рана у hashtag-scraper.
- **При провале:** причину читает сводка/`cf status --limit 5`; одиночный
  обрыв рана — повторить команду (ран ретраится и внутри, apify.run_batches);
  систематический отказ — стоп, разбор до включения таймеров.

```bash
      "| разница:", set(ref[0]) ^ set(new[0]) or "-")

bad = [(r["raw_id"], f, by_r[r["raw_id"]].get(f), r.get(f))
       for r in new if r["raw_id"] in by_r for f in ("views", "likes")
       if max(by_r[r["raw_id"]].get(f) or 0, r.get(f) or 0) > 0
       and abs((by_r[r["raw_id"]].get(f) or 0) - (r.get(f) or 0))
           / max(by_r[r["raw_id"]].get(f) or 0, r.get(f) or 0) > 0.2]
print("метрики пересечения с расхождением >20%:", bad or "нет")
unk = sum(1 for r in new if r.get("source_query") == "unknown")
print(f"unknown-атрибуция apidojo: {unk}/{len(new)} (порог <=10%)")
share = lambda rows: sum(1 for r in rows
                         if r.get("processing_status") == "raw_saved_actor_transcript") / max(len(rows), 1)
print(f"доля строк с транскриптом: clockworks={share(ref):.0%} apidojo={share(new):.0%} "
      f"(порог: apidojo >= clockworks - 15 п.п.)")
EOF
```

(подставить пути двух JSONL: эталон из 2.1, новый из 4.2 — имена печатал сам
dry-run). Что сравнивается и почему такие пороги:

- **Колонки** — 1:1, без порога: это контракт адаптера, любое расхождение —
  дефект (§3.2).
- **Объём** — apidojo ≥ 70% строк эталона. Обоснование: ленты живые и
  ранжирование у акторов разное, ±несколько роликов на 80 — норма; потеря
  >30% — это уже целый источник из батча-четвёрки, такую потерю сам конвейер
  зовёт деградацией. Деньгами недобор не страшен ($0.0003 против $0.002 —
  в 6.7 раза дешевле за строку), страшен покрытием: `min_rows`/`min_new_rows`
  фан-аута начнут голодать.
- **raw_id-пересечение** — справочно, порога нет (живая лента); у
  пересёкшихся видео метрики одного порядка (расхождение ≤20% — счётчики
  растут между ранами; больше — актор врёт в цифрах, это красное).
- **Атрибуция** — `unknown` ≤10% (атрибуция восстанавливается по полю
  `hashtags` item'а; systematic unknown = поле не то, §3.2).
- **Транскрипты** — доля `raw_saved_actor_transcript` у apidojo не ниже
  clockworks минус 15 п.п. Это и есть **явное решение о судьбе
  транскрипт-покрытия TikTok**: у apidojo текста в выдаче нет вообще, есть
  только ссылки `subtitleInformation` — их разворачивает в текст существующий
  бесплатный контур скачивания; если ссылок ощутимо меньше, чем у clockworks,
  строки будут слепыми для анализа приёмов. Слепые строки дешевле, но
  бесполезнее: $2.6/мес экономии не стоят потери сигнала — при провале этого
  порога хэштеги ОСТАЮТСЯ на clockworks-hashtag-scraper.

### 5.3 Сравнить тексты

```bash
.venv/bin/python - <<'EOF'
import json, re
refs = json.load(open("agent-runtime/collect/transcript-benchmark-refs.json", encoding="utf-8"))
items = json.load(open("agent-runtime/collect/transcript-benchmark-new.json", encoding="utf-8"))
CODE = re.compile(r"instagram\.com/(?:p|reel|reels)/([^/?#]+)", re.I)
def code(u):
    m = CODE.search(str(u or ""))
    return m.group(1) if m else ""
def text_of(item):
    for k in ("transcript", "text", "segments"):
        v = item.get(k)
        if isinstance(v, str) and v.strip(): return v
        if isinstance(v, list):
            j = " ".join((p.get("text", "") if isinstance(p, dict) else str(p)) for p in v).strip()
            if j: return j
    return ""
new_by_code = {}
for it in items:
    if not isinstance(it, dict): continue
    cde = code(it.get("url") or it.get("inputUrl")) or str(it.get("shortCode") or "")
    if cde and cde not in new_by_code: new_by_code[cde] = text_of(it)
toks = lambda s: set(re.findall(r"[а-яёa-z]{3,}", s.lower()))
def cyr(s):
    L = [c for c in s if c.isalpha()]
    return sum('а' <= c.lower() <= 'я' or c.lower() == 'ё' for c in L) / len(L) if L else 0
punct = lambda s: 100 * len(re.findall(r"[.,!?…]", s)) / max(len(s.split()), 1)
rows = []
for r in refs:
    old, new = r["old"], new_by_code.get(code(r["url"]), "")
    to, tn = toks(old), toks(new)
    rows.append({"jaccard": round(len(to & tn) / len(to | tn), 2) if to | tn else 0,
                 "len_ratio": round(len(new) / max(len(old), 1), 2),
                 "cyr_old": round(cyr(old), 2), "cyr_new": round(cyr(new), 2),
                 "punct_old": round(punct(old), 1), "punct_new": round(punct(new), 1),
                 "empty_new": not new.strip(), "url": r["url"]})
for x in rows: print(x)
med = lambda k: sorted(v[k] for v in rows)[len(rows) // 2] if rows else 0
print("медианы: jaccard =", med("jaccard"), "| len_ratio =", med("len_ratio"))
print("пар без нового текста:", sum(x["empty_new"] for x in rows), "/", len(rows))
print()
for r in refs[:5]:
    new = new_by_code.get(code(r["url"]), "")
    print("=" * 60, "\nURL:", r["url"])
    print("СТАРЫЙ:", r["old"][:300], "\nНОВЫЙ :", new[:300])
EOF
```

### 5.4 Критерий боевого доверия (все пункты разом)

- медианный **jaccard ≥ 0.5** — тексты об одном ролике (ASR-вариативность
  съедает дословность, общая лексика — нет);
- у русских пар **cyr_new ≥ 0.8 × cyr_old** — язык не потерян и не
  транслитерирован;
- медианный **len_ratio в [0.6; 1.5]** — не обрубки и не галлюцинации;
- **пунктуация нового ≥ 50%** плотности эталона — «сплошняк» без точек ломает
  читабельность для генератора брифов;
- **глазами 3–5 пар** (печатаются в конце снипета): связный русский, без
  мусорных вставок и чужого языка.

Зелёно → apple_yang в бою (он уже в конфиге — отдельного включения не надо);
вердикт и медианы — в комментарий тикета 03.

**Почему официальный откат гибрида работает** (tiktok_hashtag → значение
основного актора): маршрутизация по kind останется, но hashtag-батчи уйдут
основному актору с тем же `build_hashtag_payload` — а этот payload есть
подмножество схемы основного актора: `hashtags`, `resultsPerPage` и
`shouldDownload*` основному актору слал ещё n8n-воркфлоу (эталон
`build_search_payload`, где `hashtags` жил до тикета 02), а
`downloadSubtitlesOptions` сверен по схеме билда `latest` ИМЕННО основного
актора в тикете 01. Оговорка честности: **api-evidence.json это утверждение
подтвердить не может** — в нём только цены и статистика успеха, схем там нет
(проверено при сборке runbook); подмножество опирается на сверки схем билдов
в тикетах 01–02. Что api-evidence.json для этого отката подтверждает —
цену: строки снова станут $0.003 + actor-start $0.001/батч (вдвое дороже,
92.5% успеха против 99.8%) — откат это про надёжность формата, не про деньги.

Правка `cf.config.json` не требует рестартов: CLI и таймерные юниты читают
конфиг на каждом запуске. Если всё же нужен рестарт `cf-dashboard` — сначала
проверка локов (§1.2): рестарт убивает идущий прогон.
