## Что построить

Новая подкоманда `cf vision`: берёт строки со скачанным медиа и без разбора,
зовёт vision-движок, валидирует ответ схемой визуальных фактов (тикет 02) и
апсертит факты в Raw-вкладку по `raw_id`. Платное и лимитное звено живёт
отдельно от сбора: его падение или лимит сбор не трогают.

- Блок `vision` в `cf.config.json`: `engine`, `model`, `batch_limit`,
  `frames_enabled` (v1 — false). Переключение движка/модели стоит одну
  строку конфига.
- Интерфейс движка — единственный новый шов системы: «контекст строки +
  пути медиа → JSON визуальных фактов». Реализации v1: headless-подписка
  (`claude -p`, дефолт-гипотеза) и заготовка под API-ключ — второй
  реализацией того же интерфейса, включается конфигом.
- v1 подаёт движку только обложку (решение гриля №1). Кадры — этап 2 тем же
  интерфейсом: контракт выхода уже умеет `frame:N`, переделки не требуется.
- Экономика: vision не зовётся ни одним таймером — до расконсервации только
  руками; включение в дневной цикл — отдельное решение после пилота.

## Критерии приёмки

- [ ] Очередь: строки с `media_status` ∈ {saved, partial} и пустым
      `visual_status`; лимит партии — флаг (дефолт — из конфига).
- [ ] Пустая очередь → ни одного платного вызова, причина честно в выводе
      (существующее правило воркеров).
- [ ] Валидный ответ движка → `visual_facts` (компактный JSON, обрезка тем же
      приёмом, что raw_json — лимит ячейки 50K) и `visual_status = done`.
- [ ] Невалидный ответ или недоступное медиа → `visual_status = failed`;
      мусорный ответ модели в Sheets не попадает; строка не выглядит
      разобранной.
- [ ] Апсерт по `raw_id` не затирает прочие поля строки; повторный прогон
      идемпотентен (разобранные строки не переразбираются).
- [ ] Режим пилота: команда работает по JSONL dry-run батча — факты кладутся
      рядом в JSONL, Sheets не трогается.
- [ ] Выбор движка/модели из конфига проверяется тестом подменой значения;
      смена — одна строка `cf.config.json`.
- [ ] Каждый прогон — в Run Log со `--started-at` (правило №6).
- [ ] Реестр ожидаемых колонок обновлён (`visual_status`, `visual_facts`);
      решено и покрыто тестом, как `visual_facts` доезжает до читателей при
      проекции тяжёлых колонок (не спрятать его от анализа — тикет 07).
- [ ] Тесты с fake-движком: валидный ответ, невалидный ответ → failed,
      пустая очередь без платного вызова, лимит партии, идемпотентность,
      Run Log.
