# 08 — `visual_refs` в схемах и проверка ворот `visual_refs_resolve`

**Blocked by:** 03, 05
**Status:** done

контракт честности вниз, Testing Decisions §2).

## Что построить

Паттерны и формулы легально ссылаются на «кадр N видео X» и «обложку видео X»,
а машинные ворота рецептов детерминированно проверяют такие ссылки — выдуманный
визуальный evidence в производство не проходит (правило №1).

- Схемы паттернов и формул: evidence получает ОПЦИОНАЛЬНЫЙ `visual_refs` —
  массив `{source_url, media: "cover"|"frame", frame_index?}`. Отсутствие
  `visual_refs` легально: старые формулы и чисто текстовые паттерны не
  ломаются.
- Ворота рецептов: новая проверка `visual_refs_resolve`, применяется только
  при наличии `visual_refs`: `source_url` резолвится в raw-индексе, у строки
  `visual_status = done`, `frame_index` в пределах числа кадров манифеста.
  Raw-вкладки не прочитаны → `ok = None`, рецепт уходит к человеку
  (существующая семантика evidence-проверок).

## Критерии приёмки

- [ ] Старые формулы/паттерны без `visual_refs` валидны и проходят ворота
      как раньше; проверка на них не блокирует.
- [ ] Невалидные формы `visual_refs` (без source_url, media вне словаря,
      frame_index не число) отклоняются схемой; `cf validate` их ловит.
- [ ] Таблица тест-случаев проверки: ссылка резолвится / URL не в индексе /
      разбор не done / frame_index за пределами манифеста / Raw не
      прочитаны → ok=None (прообраз — существующая таблица тестов ворот,
      включая «непрочитанный Raw — не да»).
- [ ] Чек-лист `cf auto-approve-formula --check` показывает новую проверку
      с честной деталью.
