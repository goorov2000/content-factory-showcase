# 03 — Реестр заказов со статусами

**What to build:** Появляется реестр заказов «CF Orders» — источник истины по
деньгам с продаж. Сборщик metrika дополняется третьим запросом: e-commerce
покупки (purchase id, дата, выручка, UTM ласт-клик) → upsert кандидатов со
`status=candidate`; merge никогда не затирает решённые статусы и ручные
строки. В пульте (страница «Деньги» появится тикетом 04 — здесь достаточно
временного раздела/роутов) владелец решает судьбу кандидата кнопками:
«оплачен, не возвращён» (`confirmed`) / «возврат» (`returned`) / «не наш»
(`rejected`); решение пишет `status_changed_at`, `decided_by` и строку Run
Log. Форма ручного заказа (дата, сумма, аккаунт, комментарий) создаёт строку
`source=manual` сразу в статусе `confirmed` — для заказов, не дошедших до
e-commerce. Статусы меняет только человек; сборщик их не трогает.

**Blocked by:** 02 (клиент Метрики, паттерн вкладок).

## Комментарии

2026-07-30 — сделано, +24 теста (metrika 5: нормализация покупок, merge,
третий запрос/окно/фильтр, заморозка; actions 7; роуты /orders 11; инвариант
конфига 1), полный сьют 1845 passed. Решения по месту: (1) merge у кандидата
обновляет только снапшотные поля (`ORDER_SNAPSHOT_FIELDS`) — поля решения
человека (notes и пр.) не затираются даже у кандидатов, а пустой/чужой статус
читается как «не кандидат», то есть заморожен: при сомнении деньги не трогаем.
(2) «Передумать» у решённых — полным набором статусов, включая «Вернуть в
кандидаты» (зеркало decision=pending у ревью). (3) `order_id` ручного заказа
детерминирован от содержимого (дата|сумма|аккаунт|комментарий): даблклик не
плодит строку с деньгами; неразличимые заказы различают комментарием.
(4) Кандидаты едут в тот же dry-run JSONL, что и трафик (`summary["rows"]`) —
`src/cf/cli.py` не тронут (в нём чужие staged-ханки codex-sync).
(5) GET /orders при ещё не созданной вкладке CF Orders — честное «заказов пока
нет» (WorksheetNotFound ловится в orders_context); вкладку создаёт первый сбор
или первый ручной заказ (`ensure_tab` по той же `ORDER_HEADERS`).
(6) Атрибуция e-commerce — `lastsign*` («последний значимый»), константы в
шапке metrika.py с пометкой «подтвердить на приёмке с живым токеном».
(7) Секция — партиал `partials/orders_section.html`, страница /orders
временная, навигация base.html не тронута (перенос на /money — тикет 04).
