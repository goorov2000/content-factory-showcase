## Подкоманды и конфиг
- CLI: `.venv/bin/python -m cf <command>` (консольный `cf` — только как
  `.venv/bin/cf`, в PATH systemd/шеллов его нет). Подкоманды:
  read, profile, status, validate, add-brief, log-run (флаг `--started-at ISO8601` —
  момент старта прогона; без него длительность в Run Log нулевая), set-review,
  rejection-history, eval-prep, log-prompt-version, approve-formula, trace,
  check-commit, install-hooks, apply-niches, backfill-attribution, source-stats,
  export-seeds, apply-sources, ab-plan (план A/B
  версий промпта), mark-published (замыкание brief→reel), formula-perf
  (own_performance в approved-индексе), analyze-batch (механика анализа v2 для агентов),
  cluster-other (кластеры «other» для предложений ниш), formula-status (статус
  формулы + approved-индекс; approve пишет иммутабельный снапшот
  formulas/_approved/<ниша>/<имя>-vN.json — писать туда вручную запрещено),
  auto-approve (авто-одобрение брифа по 4 условиям + проверки ремесла
  `cf.craftcheck`; кап помечает бриф
  «отложено заводом» — из очереди внимания он уходит), retry-deferred (вернуться
  к отложенным, когда окно капа сдвинулось), recheck-briefs (пересверить УЖЕ
  одобренные и ещё не снятые сценарии проверками ремесла и отправить дефектные в
  доработку; без `--apply` только разбор, `--limit N` — размер партии. Ворота
  смотрят лишь pending, поэтому одобренное ДО появления проверки не
  пересматривается никогда: 04.08 таких нашлось 57 из 121. Снятые и уже правленные
  заводом не трогаются), revise-brief (переписать сценарий по
  замечаниям ревьюера, одна попытка на бриф), apply-prompt-candidate (правка
  ДЕЙСТВУЮЩЕГО промпта темы кандидатом в A/B, активная версия не трогается),
  gate-calibration (сверка машинного чек-листа с решениями человека),
  auto-approve-formula
  (машинные ворота рецепта: `--check` печатает чек-лист, `--review` подставляет
  вердикт судьи, `--no-judge` — только детерминированные проверки),
  install-agent (установка нового агента по черновику proposals/: промпт +
  слэш-команда одной командой человека; Codex-обёртку команды генерирует сам),
  codex-sync (перегенерировать Codex-обёртки слэш-команд в `.agents/skills/`;
  `--check` — сверка дрейфа без записи), apply-brief-prompt
  (включить промпт темы по черновику — двойник кнопки на воротах дашборда;
  `--show` печатает текст и sha, `--check` — чек-лист, `--auto` включает только
  зелёный, `--reject` отклоняет), formula-guard (авто-пауза
  формулы при 3 reject из 5 в окне текущего одобрения или по провальной
  performance-медиане P5.10; демо-замеры и вердикты демо-eval в решения не идут —
  04.08 фикция сняла с производства два живых рецепта, фильтр стоит в
  `cf.cli._measured_rows` и `cf.cli._eval_is_demo`), dashboard (локальный
  веб-пульт CF), backup/restore (датированные JSONL-снимки вкладок и точечный
  откат вкладки), archive (ротация старых raw/run_log строк в JSONL + удаление
  из Sheets), collect (сбор: tiktok|instagram|snowball|performance|metrika; `--dry-run` —
  1 батч, строки только в JSONL agent-runtime/collect/ + след в Run Log;
  источники — реестр `sources/*.json`, правится только через proposal +
  `cf apply-sources`; сборщики TikTok/IG/snowball скачивают обложку и кадры
  каждой прошедшей гейт строки в `agent-runtime/media/` — визуальный контур,
  план 2026-08-14; нарезка — потолок 120 кадров: до 2 минут посекундно,
  длиннее — растяжка по всей длительности, манифест несёт duration_sec и
  cut_mode), vision (разбор скачанного медиа в визуальные факты
  движком за конфигом `cf.config.json → vision`; платное звено отдельно от
  сбора, таймеры его не зовут; `--jsonl` — режим пилота по dry-run батчу;
  ответ валидируется схемой `visual-facts` — новый kind в `cf validate`;
  кадры — `vision.frames_enabled` + кап `vision.frames_cap` (дефолта в коде
  нет; вердикт пилота вынесен 14.08, коммит 02ac1c7: в конфиге `frames_enabled=true`, `frames_cap=30`) + выборщик `vision.frames_sampler`
  (дефолт uniform); `--frames-cap` включает кадры на один прогон поверх
  конфига (путь пилота); `--niche` — вся очередь ниши без лимита по
  умолчанию, `--redo` — ре-разбор done/failed только с явной адресацией
  `--raw-id`|`--niche`; `vision.in_cycle=true` — шаг vision в прогоне ниши
  воркера ДО анализа, умолчание false — пауза завода не трогается).
- Конфиг: `cf.config.json` (id таблицы, имена вкладок, путь к service-account ключу,
  column_aliases — маппинг колонок n8n на канонические имена). Таксономия ниш живёт в
  `prompts/agents/niche-taxonomy.json` (единственный источник истины).
  `dashboard.fanout` — пороги конвейера формул (переопределяют дефолты в
  `dashboard/runner.py`): `workers` (2, параллельных прогонов ниш), `min_rows`
  (20, «чистых» строк ниши для очереди — единый порог с профайлером), `min_views` (1000, порог
  просмотров строки), `min_new_rows` (40, сколько НОВЫХ строк должно набраться в нише
  после прошлого анализа, чтобы она вернулась в очередь; считается как максимум двух
  сигналов — строки с `collected_at` позже `meta.generated_at` прошлого анализа и
  дельта к его `total_rows`. Снятый 2026-07-26 мультипликативный `growth` при линейном
  притоке растил интервал экспоненциально и задушил очередь до нуля ниш),
  `briefs_per_formula` (2, используется генератором брифов),
  `approve_cap` (5, максимум авто-одобренных брифов одной формулы за 7 дней; читает
  `cf auto-approve`, флаг `--cap` переопределяет. Двигать синхронно с порогом в
  `prompts/agents/brief-generator.md` — иначе генератор всё равно пропустит формулу),
  `exclude_niches` ([], нецелевые ниши: классифицируются, но НЕ идут в очередь
  производства — фан-аут их пропускает, дашборд метит бейджем «ниша вне
  производства»; бренд мужской, см. docs/BUSINESS-CONTEXT.md),
  `prompt_drafts_per_run` (2, сколько черновиков промптов тем пишется за прогон),
  `autocontinue` (true, закрытие ворот само дозапускает производство сценариев;
  false — ждать ▶).
  `dashboard.creator_slots` — слоты исполнителей съёмки (`криэйтор-1`,
  `криэйтор-2`): ЗНАЧЕНИЯ ПОЛЯ, а не люди, при найме слот переименовывается одной
  правкой здесь. Их показывает кнопка «Отдал в работу» на «Очереди съёмки»
  (пустой ключ прячет кнопку с причиной), а пишутся они в колонки `creator_slot`
  и `assigned_at` листа `CF Creative Briefs` — без этих колонок назначение
  отвечает громкой ошибкой, а не теряется молча.
  Новая ниша даёт брифы только после создания `prompts/briefs/{niche}/reel.md`
  и активации prompt_versions (brief-{niche}-reel) — оба признака сводит
  `cf.dashboard.queues.prompt_state`, единственный источник готовности темы.

переопределяет. На 14.09.2026 в `cf.config.json` расходятся с дефолтами:

| Ключ | Дефолт в коде | В `cf.config.json` |
| --- | --- | --- |
| `dashboard.fanout.briefs_per_formula` | 2 | **1** (снижено 26.07, коммит 5f3b63d) |
| `dashboard.fanout.exclude_niches` | `[]` | **7 ниш**: женская-мода, знаменитости-мода, лайфстайл-мотивация, обувь, спорт-фитнес, уход-грумминг, стритвир |
| `dashboard.fanout.subprocess_timeout` | 3600 с | не задан (платный шаг убивается по этому таймауту) |
| `gates.policy` | — | ключей два: `recipes` и `prompt`, оба `auto`; у ворот сценариев рычага нет |
| `vision.frames_enabled` / `frames_cap` | нет дефолта | `true` / `30` |

Число детерминированных проверок рецепта — **12** (с 3d699d7 добавилась `visual_refs_resolve`);
точный список печатает `cf auto-approve-formula --check`. Писать число прозой в новых документах
не нужно — оно уже разошлось в восьми местах.
